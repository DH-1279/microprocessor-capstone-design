# PCB 조립 후 ESP 동작 점검 계획

작성일: 2026-10-14 · 작성자: DH(김동환)

시험 예정: **2026-10-15, 납땜 완료 후**. 사용자가 말한 ‘내일’을 작성일 기준으로 적었다. 실제 일정이 바뀌면 조립 후 같은 순서로 진행한다.

해수의 HAILO10H 모델 변환을 기다리는 동안 장갑 PCB를 독립적으로 확인한다. 첫 목표는 **ESP USB 부팅 → 채널별 모터 한 개 → 두 개·다섯 개 부하 → 정지·재부팅**이다. IMU는 전압 확인 후 추가하며, 카메라·음성·배터리 휴대 구동·BLE 통합은 이 시험의 선행 조건이 아니다.

이 문서는 준비 절차와 이후 사용자 실기 결과를 함께 기록한다. **10월 14일 사용자가 TH 채널 다이오드를 반전 재실장한 뒤 모터 동작과 약 0.05A를 확인했다.** 자세한 결과는 11장에 있다. 전체 보드의 납땜·나머지 4채널·5개 동시 구동·IMU·BLE가 통과했다는 의미는 아니다.

## 1. 준비물과 시험 전원

| 준비물 | 용도 |
|---|---|
| PCB 한 장, ESP32-C3 SuperMini 한 개 | 먼저 한 보드를 시험용으로 지정 |
| PN-VM102 모터 1개, 이후 총 5개 | 채널별 검사와 부하 시험 |
| 멀티미터 | 무전원 단락·도통, 전원 레일 전압 |
| 전류 제한 DC 전원 | 첫 모터 레일 3V 공급과 전류 확인 |
| USB 데이터 케이블, Arduino IDE | ESP 전원·업로드·시리얼 명령 |
| 인두·납·플럭스·흡납재·확대경·절연재 | 조립, 브리지 제거, 배선 고정 |
| GY-521(선택), 가능하면 오실로스코프 | IMU 확인, PWM·기동 순간 전압강하 확인 |

첫 시험에서는 배터리를 사용하지 않는다. 충전/승압 모듈이 아직 없어도 ESP USB와 모터용 DC 전원으로 진행할 수 있다. **전류 제한 전원을 준비하지 못하면 무전원 검사·USB·DRY_RUN까지만 진행한다.**

```text
PC USB ───────────────────────────────→ ESP USB-C
DC 전원 + (첫 시험 3.0V) ──────────────→ PCB 배터리 전압 레일
DC 전원 − ────────────────────────────→ PCB GND = ESP GND
PCB 외부 5V 입력 ─────────────────────→ 미연결
```

PCB 윗면의 발주 그림 기준 `PW_CONN(5,3,G)`는 왼쪽부터 **5V / 배터리 전압 레일 / GND**다. 실크의 `3`은 ESP의 `3V3` 출력이 아니라 발주 회로의 `3.7V` 네트다. **실물 도통으로 핀을 확인한 뒤** 위 배선을 연결한다. USB로 전원 공급할 때 PCB 5V 핀이 살아날 수 있으므로 외부 5V는 동시에 넣지 않는다.

PN-VM102 설명서는 기준 전압 3V, 사용 범위 2~5V, 사용 전류 약 60mA를 제시한다. 따라서 5개의 기준 동작 전류를 단순 합산하면 약 300mA지만, 이것은 **기동/최대 전류나 실제 PCB 측정 결과가 아니다.** 첫 한 개 시험은 3V에서 전류 제한을 예를 들어 0.15A로 두어 시작하고, 전원 CC 진입·기동 실패 여부를 확인한다. 이 값은 초기 시험 설정 제안이며 제조사의 기동 전류 정격이 아니다. CC에 걸린 채 모터를 오래 구동하지 않는다. 다채널 제한값은 먼저 측정한 개별 기동 전류와 공급기 여유를 기준으로 정한다. [PN-VM102 설명서](https://www.eleparts.co.kr/data/goods_old/design/product_file/Hoon/PN-VM102-K.pdf)

## 2. 납땜과 무전원 검사

USB·배터리·DC 전원을 모두 분리한다. 금속 책상이나 손 위에 두지 않고 절연된 작업면에서 진행한다.

- [ ] 보드 ID를 붙이고 앞·뒤 사진을 남긴다. 사진을 추가한다면 `images/2026-10-15/`처럼 실제 촬영 날짜 폴더를 사용한다.
- [ ] ESP 방향·핀 정렬·USB 접근, GY-521 적층 간격과 금속부 접촉 여부를 확인한다.
- [ ] 납땜부를 확대해서 인접 핀 브리지, 냉땜, 뜬 패드, 남은 금속 조각을 검사한다.
- [ ] ESP 5V, 3V3, 모터 레일과 GND 사이의 지속적인 저저항 단락 여부를 확인한다. 커패시터 충전에 따른 순간 도통음만으로 단락 판정하지 않는다.
- [ ] ESP 3V3와 모터 레일을 실수로 연결하지 않았는지 확인한다.
- [ ] 각 모터 +는 모터 공용 전원, −는 해당 MOSFET 드레인인지 대조한다.
- [ ] SS14 띠가 있는 K는 모터 +, A는 드레인인지 부품 방향과 도통으로 대조한다. 회로 내 다이오드 측정은 병렬 경로 때문에 단독 부품 측정과 다를 수 있다.
- [ ] MOSFET 소스는 GND, 게이트 직렬 100Ω과 게이트–GND 10kΩ 풀다운이 각각 있는지 확인한다.
- [ ] 아래 GPIO와 채널을 도통 검사한다. GPIO–게이트 경로에는 100Ω 저항이 있으므로 도통음 유무만으로 연결 여부를 판정하지 않는다.
- [ ] 모터선 납땜·절연·당김 방지를 확인한다. 부품을 연결하거나 배선을 바꿀 때는 다시 모든 전원을 분리한다.

| 손가락 | GPIO | PCB 모터 패드 |
|---|---:|---|
| TH 엄지 | 0 | TH+ / TH− |
| IN 검지 | 1 | IN+ / IN− |
| MI 중지 | 3 | MI+ / MI− |
| RI 약지 | 4 | RI+ / RI− |
| PI 소지 | 5 | PI+ / PI− |
| GY-521 SDA / SCL | 6 / 7 | SDA / SCL |

근거: [발주 회로와 전원 구성](2026-10-04_장갑_햅틱_PCB_발주_및_조립_준비.md). 초기 BLE 수신기 설명의 ‘임시 핀’ 표현보다 발주 기록이 이후 결정이며, 실제 납땜품은 별도로 대조해야 한다.

## 3. USB 단독 부팅과 DRY_RUN

1. 외부 전원과 모터선을 연결하지 않은 상태에서 ESP USB를 연결한다. 이미 모터가 납땜되어 있다면 최소한 모터 전원은 끈다.
2. 모듈 발열·포트 반복 끊김·이상 전류가 있으면 전원을 분리하고 2장으로 돌아간다.
3. ESP `3V3`–GND를 측정한다. 통상 약 3.3V를 기대하되 허용값은 보드/계측 조건과 함께 판단한다.
4. [새 pcb_bringup 스케치](../esp32_device/firmware/pcb_bringup/pcb_bringup.ino)를 업로드한다. 별도 NimBLE 설치는 필요 없다.
5. Arduino IDE: `ESP32C3 Dev Module`, `USB CDC On Boot: Enabled`, 시리얼 115200, 줄 끝 `새 줄`.
6. `help`, `status`를 입력하고 `mode=DRY_RUN`, `pwm=OK`, `armed=0`, `active=0`, 5채널 duty=0을 확인한다. 부팅 로그는 시리얼 모니터를 열기 전에 지나갈 수 있다.
7. 한 줄씩 `arm` → `pulse TH 96 300`을 입력한다. 내장 LED와 논리 출력만 활성화되고 물리 모터 PWM은 0이어야 한다. 300ms 이후 `status`에서 OFF를 확인한다.

`pwm=FAULT`이면 실제 출력 모드로 진행하지 않는다. RESET, USB 연결, 보드 선택을 확인하고 초기화 오류를 해결한다. 이 코드가 부팅 때 모든 MOSFET 게이트를 LOW로 설정하지만 **부팅 전·리셋 동안에는 하드웨어 풀다운이 필요하다.**

## 4. 실제 모터 한 개와 채널 분리

1. 모든 전원을 끄고 모터 한 개를 TH+/TH−에 연결한다. GY-521은 가능하면 아직 연결하지 않는다. 이미 같은 전원에 실장했다면 3V에서 IMU 동작을 요구하지 않고 `scan`/`imu`도 실행하지 않는다.
2. DC 전원 출력이 꺼진 상태로 +를 모터 레일, −를 GND에 연결한다. 설정 3V와 전류 제한을 확인한 뒤 USB, DC 전원을 켠다.
3. 모터는 아직 움직이지 않아야 한다. `status`가 DRY_RUN/OFF인지 확인한다.
4. `mode motors` → `arm` → `pulse TH 96 300`을 한 줄씩 입력한다.
5. TH만 짧게 움직이고 300ms 뒤 멈추는지, ESP가 재부팅되지 않는지 확인한다. 동작 전압·전류·CC 표시·발열을 기록한다.
6. 낮은 duty에서 안 돌면 `stop`하고 배선·MOSFET·전원 CC 상태부터 확인한다. 회로가 정상이라면 **3V를 유지한 채** `arm` → `pulse TH 160 300`, 이후 필요 시 `255`로 비교한다. PWM duty로 기동 여부를 확인하며 무작정 전압을 올리지 않는다.
7. 출력이 끊긴 뒤 모터 전원을 끄고 배선을 바꾼다. IN, MI, RI, PI를 같은 방법으로 검사한다. 한 모터를 옮겨 연결하거나 각 모터를 순서대로 추가한다.

멀티미터로 PWM 게이트를 보면 평균값이 표시될 수 있으므로 ‘HIGH=3.3V가 안 나온다’는 이유만으로 오류 판정하지 않는다. 가능하면 오실로스코프로 해당 게이트의 200Hz PWM과 다른 채널 LOW를 확인한다. 실제 다른 모터가 켜지면 채널 간 단락·배선·핀 매핑을 다시 확인한다.

**한 채널 통과:** 올바른 모터만 동작, 기동 및 정지 재현, ESP 리셋 없음, 전원 CC/이상 발열 없음. 시리얼 `OK`는 명령 수락이며 물리 동작 확인이 아니다.

## 5. 두 개 → 다섯 개, 정지와 재부팅

개별 채널을 모두 통과한 뒤 공급 전원의 제한값을 개별 측정에 맞춰 재설정하고 단계적으로 부하를 늘린다.

```text
arm
pulse TH,IN 96 300
```

두 개 시험을 확인한 뒤:

```text
arm
pulse ALL 96 300
```

각 명령 사이에 실제 정지와 전원 상태를 확인한다. 새 pulse에는 새 `arm`이 필요하다. 처음부터 5개 최대 duty를 넣거나 자동 반복하지 않는다. 300ms 펄스는 멀티미터 표시보다 짧을 수 있으므로 전원 장치의 피크/최소 기록이나 오실로스코프를 활용한다. 소프트웨어가 허용하는 최대 pulse는 1초이며, 이것만으로 발열/소비 전력 전체 시험이 끝나는 것은 아니다.

| 시험 | 입력/조작 | 통과 조건 |
|---|---|---|
| 시간 만료 | 300ms pulse 이후 대기 | 실제 모터 OFF, active=0, 다음 pulse에 arm 필요 |
| 즉시 정지 | `pulse TH 96 1000` 실행 중 `!` | 자동 만료 전 OFF; 이후 새 줄로 입력 재개 |
| arm 만료 | `arm` 후 10초 이상 대기, pulse | 거절, 모터 OFF |
| 잘못된 값 | `arm`, `pulse TH 999 300` | 거절, OFF, arm 해제 |
| USB/시리얼 끊김 | pulse 도중 모니터 닫기 또는 USB 분리 | OFF. CDC 감지와 무관하게 지정 시간 이후에는 OFF |
| RESET | pulse 도중 RESET | OFF, 재부팅 후 DRY_RUN, 자동 재구동 없음 |
| 전원 재투입 | USB/외부 전원 순서를 바꿔 재투입 | 모터가 뜻하지 않게 움직이지 않음; 풀다운 검증 |

USB 분리 시 ESP가 완전히 무전원이 될 수 있으므로 하드웨어 풀다운의 실제 정지가 특히 중요하다. DC 전원을 켜둔 상태에서 ESP 재부팅/USB 분리 시험은 배선 검사·개별 구동을 통과한 뒤 진행한다.

## 6. IMU는 나중에 확인

GY-521은 MPU6050 칩 자체와 달리 보드에 레귤레이터가 있을 수 있다. 구매 모듈의 VCC 입력 조건과 레귤레이터 출력부터 확인한다. 최종 LiPo 완충 시 약 4.2V가 모듈 VCC에 들어갈 예정이므로, 그 조건에서 SDA/SCL HIGH가 **3.3V 수준이며 ESP 허용 범위를 넘지 않는지** 확인한다. ESP GPIO를 통해 허용되지 않는 전압을 넣지 않는다. [Espressif GPIO 전압 안내](https://docs.espressif.com/projects/esp-faq/en/latest/hardware-related/hardware-design.html#what-is-the-voltage-tolerance-of-gpios-of-esp-chips)

이미 ESP와 연결된 센서 핀에 검증되지 않은 배터리 전압을 넣어 측정하지 않는다. 처음 전압을 검증할 때는 ESP의 SDA/SCL 경로를 분리할 수 있는 상태에서 측정한다. 적층 직접 납땜으로 분리가 어렵다면 먼저 구매한 예비 GY-521 단품에서 모듈 전원과 풀업 구성을 확인한다.

전압 검사 후 `scan` → `imu`:

- AD0=GND일 때 주소 `0x68`.
- WHO_AM_I=`0x68`, RAW 가속도/자이로 값 출력.
- 보드를 움직여 여러 번 `imu`를 실행했을 때 값이 변하는지 확인.
- 모터는 두 명령 모두 OFF로 만든 뒤 센서를 읽는다. 이 스케치는 모터 ON 중 IMU 잡음 측정이나 자세 보정을 하지 않는다.

IMU가 없어도 모터/BLE 기본 MVP는 진행할 수 있다. IMU 시험 때문에 모터 확인을 막지는 않는다.

## 7. BLE 통합은 직접 구동 통과 후

1. [기존 haptic_receiver](../esp32_device/firmware/haptic_receiver/README.md)를 **DRY_RUN=true**로 다시 업로드한다.
2. 장치 이름 `KIMGANE-HAPTIC`과 수신 값·정지를 확인한다. 이전 LED용 `led_control.py`는 이 수신기와 UUID/패킷이 다르다.
3. 해수 모델을 준비하고 Pi 비전 단독 동작까지 확인한 뒤 `python -m haptic_mvp run --console --ble`로 통합한다. 모델이 없으면 이 비전 통합 단계는 미룬다.
4. PCB 직접 구동이 통과했다면 `haptic_receiver`의 `DRY_RUN=false`로 전환하고, BLE STOP·TTL 만료·연결 종료 시 실제 OFF를 확인한다.

이번 시리얼 스케치는 BLE를 구현하지 않는다. 기존 BLE 수신기를 수정하거나 자동으로 덮어쓰지 않으며, `mode motors` 값이 다른 스케치에 전달되는 것도 아니다.

## 10. 시리얼 응답 문제와 수정 버전

2026-10-14 사용자가 COM11에서 `pcb_bringup` 업로드 성공 로그를 전달했다. 사용자가 빌드한 이전 버전은 프로그램 337,074바이트, 정적 RAM 15,412바이트이며 Flash 쓰기 해시 검증까지 통과했다. RESET 뒤 부팅 문구 끝의 `=3 RI=4 PI=5`는 보였지만 `status` 명령에는 응답이 없다고 보고했다. PCB 모터 구동 성공은 아직 확인하지 않았다.

로컬 Arduino-ESP32 3.3.11의 `cores/esp32/HWCDC.cpp`를 읽어 USB TX 연결 감지 값이 순간적으로 false가 될 수 있고, 수신 큐의 읽기는 이 값과 별개임을 확인했다. 이전 스케치는 `Serial` 연결 감지 값이 true일 때만 수신 바이트를 읽으며, false 전환마다 입력을 폐기했다. 이 조건은 정상적으로 도착한 명령도 막을 수 있다. 실제 사용자 보드의 원인이 이 조건인지 최종 확정한 것은 아니며 수정본 재업로드로 확인한다.

수정 사항:

- 수신 큐에 데이터가 있으면 연결 감지 값과 무관하게 읽는다.
- 연결 상실은 감지 값 false가 500ms 지속되고 새 수신 데이터가 없을 때만 보조 정지 조건으로 처리한다. pulse 자체의 최대 1초 제한은 유지한다.
- 연결 상실 때 미완성 입력이 있던 경우에만 해당 줄을 폐기한다. 정상적인 첫 새 `status` 줄이 무조건 폐기되지 않는다.
- 2초마다 `BENCH v2 | rx=... | lines=... | uptime_ms=...`를 출력한다. 부팅 로그를 놓쳐도 수정 버전의 실행 여부를 확인할 수 있다.

| 수정 버전 검증 | 결과 |
|---|---|
| 파서·시간 제한·프레이밍·연결 감지 검사 | **17,750개 통과**, MSVC C++17 `/W4 /WX /analyze` 진단 없음 |
| 실제 `.ino` 제어 흐름 회귀 검사 | **23개 통과**, 대체 Arduino/PWM/Serial API에서 실제 setup/loop/출력 작업을 실행. false 연결 감지 중 status 처리, 재연결 첫 명령, 정지·PWM 실패 등을 확인. 실제 USB 드라이버나 전기 회로·스레드 스케줄링 시험은 아님. |
| ESP32-C3 컴파일 | Arduino-ESP32 3.3.11, USB CDC Enabled, `--warnings all` 통과, 진단 없음 |
| 저장 공간 / 정적 RAM | **337,154바이트(25%) / 15,428바이트(4%)** |
| 수정 버전 실기 | 사용자 재업로드 후 status 응답, pwm=OK, rx/lines 증가 확인. TH 모터 수리 결과는 11장. |

재확인 순서: 외부 모터 전원 OFF → 수정 파일 재업로드 → 시리얼 115200/새 줄 → 2초 주기 `BENCH v2` 확인 → `status` 전송. `rx`와 `lines`가 늘고 `STATUS` 응답이 나오면 명령 처리까지 확인한 것이다. `pwm=OK`, DRY_RUN/OFF를 확인한 뒤에만 실제 모터 시험으로 진행한다.

### 전기적 극성과 라이브러리 대응

모터를 분리한 TH 양단의 사용자 최종 측정 결과:

| 프로브 | 수리 전 표시 |
|---|---|
| 빨강 TH− / 검정 TH+ | **OL**. 사용자가 먼저 적은 `0.0000`을 이후 `OL`로 정정했으므로 OL을 최종 결과로 기록한다. |
| 빨강 TH+ / 검정 TH− | **0.198V** |

정상 보호 다이오드는 A가 모터 −, K가 모터 +에 연결되므로 반대 방향의 측정 패턴을 기대한다. 위 결과는 모터 +에서 모터 −로 순방향 도통하는 역방향 실장과 일치한다. 실물 SS14의 몸체 띠가 K(캐소드)를 뜻한다. PCB 실크의 막대나 심볼의 A/K 글자와 구분해야 한다. [SS14 데이터시트의 극성 설명](https://www.mdddiodes.com/wp-content/uploads/2022/08/SMASS140000S14.pdf#page=4)

로컬 EasyEDA 원본의 TH 채널은 Q1/D2다. D2 패드 1은 `Q1_3`(TH−), 패드 2는 `3.7V`(TH+)에 연결된다. 사용한 회로 심볼은 1=A, 2=K이지만 풋프린트의 극성 막대는 패드 1 쪽에 표시되어 있다. 따라서 **회로도 A→드레인/K→전원 + 배선은 맞아도, 심볼과 풋프린트의 극성 대응을 별도로 대조해야 한다.** 이전 회로 검토에서 이 대응과 실물 극성을 충분히 검증하지 못했다.

실물 사진에 D5/D4 몸체 띠가 모터 − 쪽으로 보이는 점은 추가 검사 근거다. 해당 사진에 D2는 담기지 않았으며, TH의 원인 판단에는 사용자 다이오드 측정과 반전 재실장 전후 결과를 사용한다. 나머지 채널이 모두 수리·통과했다고 기록하지 않는다.

### 수리와 확인된 결과

**사용자가 D2를 뒤집어 재실장한 뒤 모터가 동작하고 파워서플라이 전류가 약 0.05A로 내려갔다고 확인했다.** 이는 **50mA**로, PN-VM102 설명서의 3V 기준 약 60mA와 비슷한 수준이다. 이 개입 전후 변화로 TH 채널의 과전류 원인을 다이오드 역방향 연결로 판단한다. 최종 시험의 전압·duty·시간, 기동 피크·온도는 아직 전달되지 않았다. [PN-VM102 사양](https://www.eleparts.co.kr/data/goods_old/design/product_file/Hoon/PN-VM102-K.pdf)

정상 재실장 및 무전원 재검사 기준:

- 실제 몸체 띠(K) → 모터 + / 3.7V 레일.
- 띠 없는 쪽(A) → 모터 − / MOSFET 드레인.
- 모터를 분리하고 전원·USB를 모두 분리한 다이오드 모드에서 빨강 모터 − / 검정 모터 +는 순방향 전압, 반대 방향은 안정화 후 OL을 기대한다. 회로 내 다른 경로로 판단이 애매하면 다이오드를 분리하여 단독 검사한다.

### 다음 확인과 제작용 파일 수정

1. 수리한 TH 채널에서 실제 정지·시간 만료·RESET 후 OFF와 단시간 발열·전류를 확인하고 시험 조건을 기록한다.
2. IN/MI/RI/PI 보호 다이오드를 각각 무전원 검사한다. 역방향으로 확인된 부품을 수정하고 한 채널씩 시험한다. TH 한 개의 50mA 결과만으로 ALL 명령을 바로 시험하지 않는다.
3. 모든 개별 채널이 통과한 뒤 두 개 → 다섯 개로 부하를 늘리고 전압강하·리셋·정지를 확인한다.
4. 다음 제작 전에는 심볼의 물리 핀 번호와 실제 풋프린트 K/A 패드를 일치시킨다. 현재 풋프린트의 K 쪽이 패드 1인 구성이라면 심볼 K=1, A=2로 대응하도록 수정하고 PCB 갱신·재배선·극성·CPL 방향을 검증한다. A/K 글자만 바꾸지 않는다. [EasyEDA 핀·패드 대응 안내](https://docs.easyeda.com/en/PCBLib/PCBLib-Create/)

**이 작업에서 EasyEDA 원본이나 제작 파일을 수정한 것은 아니다.** 기존 PCB 수리는 현재 동박 연결을 기준으로 하고, 이후 수정한 설계의 부품 방향을 기존 보드에 그대로 적용하지 않는다. GY-521의 실제 연결·입력/풀업 전압 검증, 배터리·BLE·전체 5채널 실기 검증은 남아 있다.

## 12. 최신 main과 오늘 로컬 작업의 차이
