# ESP32-C3 초기 구동 및 개발환경 설정

- 작업일: 2026-09-15 (한국 시간)
- 프로젝트: 김가네 비전 기반 햅틱 글러브
- 작업 대상: ESP32-C3 SuperMini 보드 1개
- 근거: 사용자와의 설정 과정, 사용자가 제공한 업로드 로그와 시리얼 출력
- 결과: 컴파일·업로드·기록 데이터 검증 성공, USB 시리얼을 통한 프로그램 실행 확인

## 1. 오늘 진행한 작업

1. 수령한 ESP32-C3 SuperMini를 USB만 연결한 상태에서 시험했다.
2. 업로드 전부터 USB 포트가 반복해서 연결·해제되는 증상을 확인했다.
3. BOOT 버튼을 누른 채 RESET을 눌렀다 놓고 BOOT를 놓아 다운로드 모드로 진입했다. 사용자는 이 상태에서 포트가 유지됨을 확인했다.
4. Arduino IDE의 ESP32 보드 지원 패키지 설치와 대상 보드 선택을 진행했다.
5. `Missing FQBN` 오류를 해결하고 기본 동작 확인 스케치를 업로드했다.
6. 플래시 기록 후 해시 검증 성공과 시리얼 주기 출력을 확인했다.
7. 사용자가 정리한 새 폴더 구조를 개발 기준으로 반영했다.

## 2. 개발환경과 설정

| 항목 | 확인 내용 |
|---|---|
| 운영체제 | Windows |
| 개발 도구 | Arduino IDE. 정확한 IDE 버전은 확인하지 않음 |
| 보드 패키지 | esp32 by Espressif Systems, 업로드 경로상 버전 3.3.11 |
| 보드 선택 | ESP32C3 Dev Module |
| USB 설정 | USB CDC On Boot: Enabled로 안내. USB 시리얼 출력 확인 |
| 시험 포트 | COM11. 다른 PC 또는 재연결 시 번호가 달라질 수 있음 |
| 시리얼 모니터 | 115200 baud |
| 업로드 도구 | esptool v5.3.1 |
| 업로드 전송 속도 | 로그에서 921600 baud로 전환 확인 |
| 칩 | ESP32-C3 (QFN32), revision v0.4 |
| 내장 플래시 | 4MB, XMC |
| 크리스털 | 40MHz |
| USB 방식 | USB-Serial/JTAG |

Arduino IDE의 추가 보드 매니저 URL:

```text
https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

보드 매니저에서 `esp32`를 검색해 제작자가 `Espressif Systems`인 패키지를 설치한 뒤 대상 보드와 COM 포트를 각각 선택한다. COM 포트만 선택하는 것으로 대상 보드 선택을 대신할 수 없다.

## 3. 시험 코드

- 파일: [board_bringup.ino](../esp32_device/firmware/board_bringup/board_bringup.ino)
- 일반적인 검정색 SuperMini의 내장 LED 핀인 GPIO8을 사용한다. 실제 보드 리비전의 LED 회로가 다르면 핀과 활성 레벨을 확인한다.
- `millis()`를 이용해 500ms마다 LED 상태를 전환하고 `tick`, `uptime_ms`를 출력한다.
- `Serial.begin(115200)`으로 시리얼 출력을 초기화한다.
- 센서, 모터, 배터리 및 무선 통신은 이번 스케치에서 사용하지 않는다.

이번에 제공된 증거는 시리얼 출력과 업로드 로그다. LED의 실제 점멸은 사용자의 별도 관찰 결과가 없어 검증 완료 항목에 포함하지 않는다.

## 4. 발생한 문제와 처리

### USB 포트가 반복해서 사라짐

- 발생 조건: 사용자 코드 업로드 전, USB만 연결된 상태.
- 처리: BOOT를 누른 채 RESET을 눌렀다 놓고 BOOT를 놓아 다운로드 모드로 진입.
- 확인: 사용자가 다운로드 모드에서 포트가 유지된다고 보고.
- 해석: 기존 플래시 내용이나 부팅 과정이 원인일 가능성을 시사하지만, 리셋 원인 로그·전압 측정이 없으므로 원인을 확정하지 않는다. 다운로드 모드에서는 소비전류가 달라질 수 있어 전원·접촉 문제를 완전히 배제하지 않는다.
- 후속 결과: 테스트 스케치 업로드와 연속 시리얼 출력에 성공. 장시간 연결 안정성 시험은 아직 수행하지 않았다.

### Missing FQBN

```text
Missing FQBN (Fully Qualified Board Name)
Compilation error: Missing FQBN (Fully Qualified Board Name)
```

컴파일할 대상 보드가 지정되지 않은 상태에서 발생했다. ESP32 보드 패키지 설치와 `ESP32C3 Dev Module` 선택을 안내한 후 컴파일·업로드가 성공했다.

## 5. 업로드 검증 결과

사용자 제공 로그의 주요 결과:

| 항목 | 결과 |
|---|---|
| 프로그램 저장 공간 | 296,418 / 1,310,720 bytes, IDE 표시 22% |
| 전역 변수 메모리 | 14,484 / 327,680 bytes, IDE 표시 4% |
| 남은 동적 메모리 | 313,196 bytes |
| 칩 연결 | Connected to ESP32-C3 on COM11 |
| 기록 대상 | bootloader, partition table, boot_app0, application |
| 기록 검증 | 각 대상에 대해 Hash of data verified |
| 업로드 종료 | Hard resetting via RTS pin... |

`Hard resetting via RTS pin`은 업로드 후 프로그램을 실행하기 위한 재시작 메시지이며, 이 로그에서 업로드 오류는 나타나지 않았다.

IDE의 스케치 저장 공간 최대값은 현재 파티션의 애플리케이션 용량이며, 보드 전체 플래시 4MB와 구분한다.

## 6. 실제 실행 확인

사용자가 공유한 연속 출력은 `tick=34`부터 `tick=44`, `uptime_ms=17000`부터 `22000`까지다. 그중 일부는 다음과 같다.

```text
C3 SuperMini OK | tick=34 | uptime_ms=17000
C3 SuperMini OK | tick=35 | uptime_ms=17500
C3 SuperMini OK | tick=36 | uptime_ms=18000
...
C3 SuperMini OK | tick=44 | uptime_ms=22000
```

- `tick`은 1씩, `uptime_ms`는 500씩 증가했다.
- 제공된 17~22초 구간에서 프로그램의 카운터가 초기화되지 않고 주기적으로 출력되었다.
- 위 구간의 기본 실행은 확인했으나, 장시간 시험이나 실제 모터 부하 상태의 안정성을 검증한 것은 아니다.

## 7. 현재 프로젝트 구성과 폴더 기준

현재 구성은 카메라 1대 사용 방향, 장갑당 손가락별 모터 5개이며 장갑 PCB는 사용자가 설계한다. 이번 시험은 장갑 제어 보드의 첫 구동 확인이다.

| 저장소 루트 기준 경로 | 내용 |
|---|---|
| `00. 캡스톤 관련 문서/` | 학교 안내자료, 신청서, 부품표. 로컬 관리 |
| `01. 학교 실습/` | 학교 실습 코드와 결과물 |
| `03. 김가네 캡스톤 디자인/esp32_device/firmware/` | ESP32 시험 코드 및 장갑 펌웨어 |
| `03. 김가네 캡스톤 디자인/esp32_device/` | ESP32 핀맵 등 장갑 관련 자료 |
| `03. 김가네 캡스톤 디자인/Raspi5_vision/` | 라즈베리파이 영상 처리 및 통신 코드 |
| `03. 김가네 캡스톤 디자인/docs/` | 설계·회의·개발·실험 기록 |
