## 확정한 GPIO 배치

GPIO 번호는 ESP32 신호 이름이다. EasyEDA 심벌의 물리 핀 번호와 혼동하지 않는다.

| 기능 | GPIO | 네트 라벨 | 연결 대상 |
|---|---:|---|---|
| 엄지 | 0 | `TH_GPIO` | R1 100Ω → Q1 게이트 |
| 검지 | 1 | `IN_GPIO` | R2 100Ω → Q2 게이트 |
| 중지 | 3 | `MI_GPIO` | R3 100Ω → Q3 게이트 |
| 약지 | 4 | `RI_GPIO` | R4 100Ω → Q4 게이트 |
| 소지 | 5 | `PI_GPIO` | R5 100Ω → Q5 게이트 |
| I²C 데이터 | 6 | `SDA` | GY-521 SDA |
| I²C 클록 | 7 | `SCL` | GY-521 SCL |
| 내장 LED | 8 | 기존 펌웨어의 LED 핀 | 모터/센서 신호와 분리 |

현재 펌웨어의 `MOTOR_PINS = {0, 1, 3, 4, 5}`와 순서가 일치한다. `DRY_RUN = true` 상태이므로 실제 모터 출력 활성화는 하드웨어 준비 후 별도 작업이다.

SuperMini 핀 안내 그림에는 SDA=GPIO8, SCL=GPIO9가 표시돼 있지만, ESP32의 I²C 핀은 코드에서 지정할 수 있다. 내장 LED는 GPIO8에 물리적으로 연결돼 있어 코드의 핀 번호를 바꾸는 것만으로 옮겨지지 않는다. 이번에는 센서 통신과 LED 사용을 분리하기 위해 SDA=6, SCL=7로 결정했다.

센서 코드를 추가할 때 초기화 예시:

```cpp
#include <Wire.h>

// setup()에서 호출. 이번 기록에서는 코드에 추가하지 않았다.
Wire.begin(6, 7);  // SDA, SCL
```

## 모터 회로 수정 및 재확인

| 항목 | 발견한 문제 | 마지막 저장본에서 확인한 상태 |
|---|---|---|
| SS14 방향 | A가 배터리 +, K가 드레인에 연결됨 | A → 드레인/모터 −, K → 모터 +로 수정 |
| 모터 + 공통 전원 | 다이오드 수정 과정에서 전원 버스가 분리됨 | TH+·IN+·MI+·RI+·PI+가 배터리 + 버스에 연결됨 |
| 10kΩ 풀다운 | 처음에는 소스와 GND 사이에 직렬로 추가됨 | 게이트와 GND 사이로 이동 완료 |
| MOSFET 소스 | 10kΩ을 거쳐 GND에 연결됨 | 소스 → GND 직접 연결 복원 |
| 제어 신호 | ESP GPIO 쪽 라벨 누락 | 5채널 라벨 연결 완료 |
| GPIO5 라벨 | GPIO4와 같은 `RI_GPIO`가 중복됨 | GPIO5를 `PI_GPIO`로 변경 완료 |

한 채널의 기준 연결:

```text
GPIO ── 100Ω ──●── MOSFET 게이트(G)
               │
              10kΩ
               │
              GND

MOSFET 소스(S) ── GND
MOSFET 드레인(D) ── 모터 −
모터 + ── VMOTOR

SS14 A ── 모터 − / 드레인
SS14 K ── 모터 + / VMOTOR
```

다이오드는 모터 양단에 병렬로 연결하며, 모터를 끌 때 발생하는 유도성 전류의 순환 경로를 제공한다. 실제 SS14의 띠는 K(캐소드)를 나타내며 PCB 풋프린트의 패드 번호·극성은 제작 전에 별도로 대조해야 한다.

`TH_GPIO` 같은 제어 네트와 `TH-` 같은 드레인 네트는 서로 다른 신호다. 모터 선을 직접 납땜하더라도 채널별 +/− 납땜 패드 또는 관통홀은 필요하며, 네트 라벨만으로 패드가 생기지 않는다. 현재 원본에는 모터 납땜용 부품/패드가 아직 추가되지 않았다.

## GY-521 센서 핀

| 핀 | 마지막 확인 상태 | 비고 |
|---|---|---|
| VCC | 배터리 `3.7V`에 연결 | 전원부 작업 시 모듈 사양에 맞춰 재검토 |
| GND | 공통 GND | 연결 확인 |
| SDA | ESP GPIO6 | 연결 확인 |
| SCL | ESP GPIO7 | 연결 확인 |
| AD0 | GND | I²C 주소 `0x68`로 선택 |
| INT | 미사용 표시(×) | 초기에는 주기적으로 값을 읽는 방식 사용 예정 |
| XDA·XCL | 미사용 표시(×) | 추가 센서용 보조 I²C 버스는 사용하지 않음 |

심벌에는 `ADO`처럼 표기돼 있지만, 센서 주소 선택 신호는 숫자 0을 쓰는 `AD0`다. 모듈 VCC 입력 조건과 MPU6050 칩 자체의 전원 조건은 구분해야 한다. 구매한 모듈의 레귤레이터와 SDA/SCL 풀업 전압은 아직 확인하지 않았다.

## 전원 및 사용 시간 검토

PN-VM102 설명서는 기준 전압 3V, 사용 범위 2~5V, 사용 전류 약 60mA를 안내한다. 실제 구매품이 이 사양과 일치한다면 모터에 1셀 배터리 전압을 공급하는 구성이 가능하지만, 전압과 잔량에 따라 전류·진동 세기가 달라진다. 3V에서의 60mA를 4.2V에서의 최대 전류 또는 기동 전류로 사용하면 안 된다.

SS14 C2480의 정격은 1A·40V로 보호 다이오드 후보로 적합하다. AO3400A는 게이트 전압 2.5V에서도 ON 저항이 규정돼 있어 ESP의 3.3V 제어 신호에 적합하다. 실제 기동 전류와 반복 구동 발열 검증은 남아 있다.

대화에서 사용한 초기 사용 시간 계산은 다음 가정에 따른 단순 예산이다.

- 모터 1개당 60mA로 가정.
- BLE 동작 중 ESP·센서·전원부의 배터리 측 평균 전류를 80mA로 가정. 실측값이나 제조사 보장값이 아니다.
- 1000mAh 중 유효 용량을 800mAh로 가정.
- 계산식: `예상 시간(h) = 유효 용량(mAh) / 평균 배터리 전류(mA)`.

| 사용 패턴 | 가정한 평균 전류 | 계산 결과 |
|---|---:|---:|
| 모터 5개 계속 ON | 380mA | 약 2.1시간 |
| 모터 5개를 시간의 절반만 ON | 230mA | 약 3.5시간 |
| 평균적으로 모터 1개 계속 ON | 140mA | 약 5.7시간 |

이 표는 보장 사용 시간이 아니다. 특히 배터리 직결 모터의 전류 변화와 실제 전압 변환 효율을 모델링한 값이 아니다. 절반의 시간만 켜는 조건도 PWM 듀티 50%와 동일한 소비 전류를 보장하지 않는다. 전원 구성을 정한 뒤 실제 배터리 측 평균 전류로 다시 계산한다. 배터리 용량과 별도로 허용 연속/순간 방전 전류 및 보호회로 차단 조건도 확인해야 한다.

## 다음 작업: 전원부 및 제작 전 확인

**마지막 저장본에는 배터리 `3.7V`가 ESP의 `3V3` 핀에 직접 연결돼 있다. 일반적인 1셀 리튬폴리머 배터리의 완충 전압은 4.2V이므로 이 연결을 유지한 채 전원을 인가하지 않는다.**

다음 작업에서 검토할 구조:

```text
1셀 배터리 + ──┬── 모터 전원 VMOTOR
               └── 3.3V 전압 조정 회로 ── ESP 3V3

배터리 − / ESP GND / 센서 GND / MOSFET 소스 ── 공통 GND
```

- [ ] 배터리 → ESP 3V3 직결을 제거하고 전압 조정 회로 설계. 방전 말기에도 3.3V를 유지하려면 승강압 방식 검토.
- [ ] 레귤레이터의 입력 범위, 출력 전류, 과도 응답 및 권장 커패시터 확정.
- [ ] 충전 방식, 배터리 보호, 전원 스위치, USB와 배터리 동시 연결 시 역급전 방지 검토.
- [ ] GY-521 모듈의 입력 전압과 SDA/SCL 풀업 전압 확인 후 전원 연결 확정.
- [ ] 모터 직결용 납땜 패드, 전선 고정 방법 및 실크 극성 표시 추가.
- [ ] 모터 전원 디커플링, 전류 경로와 패턴 폭, ESP 안테나 주변 배치 검토.
- [ ] 실물 커넥터 극성과 심벌–풋프린트 핀 대응 확인 후 ERC/DRC 수행.
- [ ] 전원부 검증 후 센서 통신, 모터 1개 및 5개 동시 기동, BLE 유지 여부와 배터리 전류 측정.
- [ ] 센서 초기화 코드를 추가하고, 모터 구동 준비가 끝난 뒤 펌웨어의 DRY_RUN 해제 여부 결정.
