# ESP32 BLE 수신 규격 — 후속 라즈베리 송신부 기준

작성일: 2026-10-27. 이 문서는 현재 `firmware/ble_final_receiver`에 구현된 규격을 설명한다. **라즈베리 통합 코드가 안정된 뒤 이 규격에 맞춰 송신부를 연결한다. 지금은 라즈베리 코드를 수정하지 않는다.**

## 1. 역할과 데이터 흐름

```text
라즈베리: 손·목표 추적 → 왼손 자세 반영 → 모드/거리 구간/채널 선택
    ↓ 16바이트 BLE 명령 (이후 구현·연결)
ESP32: 검증 → ON/OFF 패턴 생성 → GPIO0/1/3/4/5 PWM
```

카메라 해상도, px 거리 계산, 손바닥·손등 판별 방식이 바뀌어도 아래 패킷 의미를 유지하면 ESP를 다시 수정할 필요가 없다. ESP가 받는 채널은 **최종 결정된 물리 모터 번호**다. 좌표·손바닥 플래그·목표 라벨은 전송하지 않는다.

왼손을 뒤집은 뒤 소지 쪽을 안내해야 한다면 라즈베리가 채널 4(PI)를 보낸다. ESP가 손바닥/손등을 판단하거나 TH↔PI를 자체 교환하지 않는다.

| 스케치 | `firmware/ble_final_receiver/ble_final_receiver.ino` |

## 3. 16바이트 명령

uint16은 little endian이다. 파이썬으로 구현할 경우 형식은 `<BBHHBBBB5BB`이지만 특정 언어나 파일 구조를 강제하지 않는다.

| 바이트 | 이름 | 일반 명령 값 |
|---|---|---|
| 0 | version | 2 |
| 1 | flags | 0. 정지는 bit0=1 |
| 2–3 | sequence | 0..65535, 명령마다 증가·순환 |
| 4–5 | ttl_ms | 100..1000. 시작 권장값 500 |
| 6 | mode | 2=간격 안내, 3=방향+근접 안내 |
| 7 | zone | 0=far, 1=middle, 2=near |
| 8 | channel | TH=0, IN=1, MI=2, RI=3, PI=4 |
| 9 | reserved | 반드시 0 |
| 10–14 | duties | TH/IN/MI/RI/PI 보정 duty, 각각 1..255 |
| 15 | reserved | 반드시 0 |

`duties` 5개는 다섯 모터를 동시에 켜라는 뜻이 아니다. 선택된 모터가 ON인 구간에 해당 채널의 값 하나만 사용한다. 나머지는 OFF다. 같은 채널은 거리 구간이 변해도 보정 세기를 유지한다.

일반 명령에는 5개 duty가 모두 1..255여야 한다. 전체 OFF는 duty를 0으로 채운 일반 명령이 아니라 **STOP 형식**으로 보낸다.

## 4. 두 모드의 실행 의미

### mode=2: 지정 손가락 + 간격

시험 한 회차 동안 송신부가 채널을 고정한다. 예를 들어 검지를 쓰면 channel=1이다. ESP는 요청된 채널을 실행하므로, 고정 채널 정책은 후속 송신부에서 유지한다.

| zone | ON | OFF | 반복 주기 |
|---|---:|---:|---:|
| far=0 | 200ms | 1000ms | 1200ms |
| middle=1 | 200ms | 500ms | 700ms |
| near=2 | 200ms | 200ms | 400ms |

### mode=3: 방향 채널 + 간격 / 근접 이벤트

후속 송신부의 초기 방향 약속은 다음과 같다. 이는 사용자가 익혀야 할 규칙이며 최종 사용자 평가 전의 배치다.

| 손 기준 방향 | 채널 |
|---|---|
| 엄지 쪽 | TH=0 |
| 소지 쪽 | PI=4 |
| 손끝 쪽 | IN=1 |
| 손목 쪽 | RI=3 |
| 영상상 근접 | MI=2 |

- far/middle은 선택한 방향 모터에 위 표의 간격으로 반복한다.
- near는 **channel=2만 허용**하며, 120ms ON → 120ms OFF → 120ms ON 후 OFF다.
- mode=3의 far/middle에서 MI는 사용할 수 없다.
- near를 같은 모드·구간·채널로 계속 갱신해도 두 번 진동을 반복하지 않는다. 구간을 벗어났다가 near로 재진입하거나 STOP 뒤 다시 시작하면 새 이벤트가 된다.
- near는 접근 알림이며, 실제 접촉·집기 완료를 뜻하지 않는다.

## 5. STOP / 갱신 / 만료

STOP은 version=2, flags=1, 정상 sequence·TTL을 사용하고 **바이트 6–15를 전부 0**으로 보낸다.

후속 송신부는 다음을 지켜야 한다.

1. 안내 중에는 약 100ms 간격으로 **새 sequence**를 보낸다. 같은 바이트를 반복 쓰면 중복 명령으로 거절되고 출력이 꺼진다.
2. 유효한 갱신은 TTL만 연장한다. mode/zone/channel이 같으면 진동 위상은 다시 시작하지 않는다. 해당 셋 중 하나가 바뀌면 새 패턴을 시작한다.
3. STOP은 즉시 송신한다. 손·목표 상실, 음성 정지, 오래된 영상, 실행 종료에 대한 판단은 라즈베리 쪽 책임이다. ESP는 카메라 입력의 실제 나이를 알 수 없다.
4. 라즈베리가 갱신을 멈추면 마지막 ESP 수신부터 TTL 뒤 모든 출력이 만료된다. BLE 연결 종료 이벤트에서도 OFF한다. 반영에는 약 5ms 작업 주기와 스케줄링 지연이 추가된다.
5. 신규 연결에서는 sequence 추적이 초기화된다. 일반 명령의 이전 번호 대비 순환 차이는 1..32767이어야 한다. 유효한 STOP은 과거 번호도 수락하되 마지막 번호를 뒤로 돌리지 않는다.
6. 2안 far 주기는 1200ms로 최대 TTL보다 길다. **단 한 번의 쓰기로 반복 패턴 전체를 확인할 수 없으며 지속 갱신이 필요하다.**

잘못된 길이·버전·예약값·번호·TTL·모드 조합은 모든 출력을 0으로 만든다. 출력 하드웨어 오류는 재부팅까지 유지된다.

## 6. 단발 Hex 예시

아래는 duty=180, TTL=500ms이며 서로 다른 sequence를 사용한다. 일반 BLE GATT 도구의 Hex 쓰기로 패킷 수락·단발 반응을 확인할 때 사용할 수 있다. 반복 패턴 검증은 새 번호를 주기적으로 보내야 한다.

```text
# seq=1, mode=2, far, IN
02 00 01 00 F4 01 02 00 01 00 B4 B4 B4 B4 B4 00

# seq=2, mode=3, middle, TH
02 00 02 00 F4 01 03 01 00 00 B4 B4 B4 B4 B4 00

# seq=3, mode=3, near, MI (두 번 진동 한 회)
02 00 03 00 F4 01 03 02 02 00 B4 B4 B4 B4 B4 00

# seq=4, STOP
02 01 04 00 F4 01 00 00 00 00 00 00 00 00 00 00
```

DRY_RUN=true에서는 실제 모터가 켜지지 않는다. 상태 패킷과 LED는 논리 출력 확인용이다. 실제 모터 시험은 점검한 PCB에서 DRY_RUN=false로 업로드한 뒤 수행한다.

## 7. 16바이트 상태

| 바이트 | 의미 |
|---|---|
| 0 | 버전 2 |
| 1 | bit0 연결 / bit1 명령 활성 / bit2 TTL 만료 / bit3 무효 명령 / bit4 DRY_RUN / bit5 하드웨어 오류 |
| 2–3 | 마지막 수락 sequence |
| 4–5 | 남은 TTL |
| 6–8 | 마지막 mode / zone / channel |
| 9 | 현재 논리 ON=1 / OFF=0 |
| 10–14 | 현재 논리 duty 5개 |
| 15 | 예약 0 |

반복 패턴의 OFF 구간이나 3안 근접 이벤트 완료 후에는 **명령 활성(bit1)=1이면서 현재 ON=0**일 수 있다. 이는 오류가 아니다. 수신기가 패턴과 TTL을 계속 관리하고 있다는 뜻이다. 모터 전류·회전·실제 진동을 측정한 값은 아니다.

## 8. 다음 작업의 경계

현재 ESP의 패킷 검증·2안/3안 패턴·TTL·연결 종료 OFF 코드는 준비되어 있다. 기존 PC C++ 검사 12,523개와 두 DRY_RUN 설정의 ESP32-C3 빌드가 통과했다. 이번 규격 정리는 펌웨어 동작을 변경하지 않았다.

라즈베리 쪽 이슈 수정이 끝나면 송신부에서 `mode`, `zone`, `channel`, `duties`, `sequence`, `ttl_ms`를 만들어 이 규격으로 보내면 된다. 앞서 작성한 라즈베리 송신 초안은 이번 ESP 업로드 범위에서 제외한다. 최종 팀원 코드의 상태·좌표 형식에 맞춰 송신부를 수정하거나 새 파일을 작성한다.
