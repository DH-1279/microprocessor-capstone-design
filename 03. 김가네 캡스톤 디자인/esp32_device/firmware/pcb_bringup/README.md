# 장갑 PCB 시리얼 점검 스케치

작성일: 2026-10-14

라즈베리·카메라·BLE 없이 ESP32-C3 SuperMini, MOSFET, 모터 배선 및 선택적인 GY-521을 시험한다. 내일 조립 후 진행할 상세 순서는 [PCB 조립 후 ESP 동작 점검](../../../docs/2026-10-14_DH_PCB_조립후_ESP_동작점검.md)에 있다. 이 스케치는 `haptic_receiver`와 별도로 업로드하는 시험용 프로그램이며, 동시에 BLE 수신기로 동작하지 않는다.

## 준비와 업로드

- **먼저 전원 단락·핀 순서·다이오드·풀다운·납땜을 검사한다.** 소프트웨어는 전원 회로의 단락을 검출하지 못한다.
- ESP는 USB 전원, 모터는 PCB의 배터리 전압 레일에 연결한 **별도 전류 제한 DC 전원**으로 공급한다. GND를 공통 연결한다. 외부 5V는 동시에 넣지 않는다.
- 첫 시험은 모터 레일 3V, 모터 한 개부터 한다. 모터에 ESP `3V3`를 사용하지 않는다.
- Arduino IDE에서 `pcb_bringup.ino`를 연다. 같은 폴더의 `bench_control.h`도 함께 있어야 한다.
- 보드 `ESP32C3 Dev Module`, `USB CDC On Boot: Enabled`, 시리얼 모니터 **115200 / 새 줄**. Arduino-ESP32 **3.x**용이다. 추가 라이브러리는 필요 없다.
- 시리얼 모니터가 부팅 로그를 놓쳐도 `status`와 `help`를 입력해 확인할 수 있다.
- 수정 버전은 2초마다 `BENCH v2 | rx=0 | lines=0 | uptime_ms=...`를 출력한다. `rx`는 읽은 입력 바이트 수, `lines`는 처리한 비어 있지 않은 명령 줄 수다. `status`를 전송하면 두 숫자가 늘고 STATUS 응답이 나와야 한다.

| 기능 | GPIO |
|---|---:|
| TH / IN / MI / RI / PI | 0 / 1 / 3 / 4 / 5 |
| GY-521 SDA / SCL | 6 / 7 |
| 내장 LED(시험한 SuperMini의 active LOW) | 8 |

## 명령

명령어는 소문자, 채널 이름은 대문자다. 시간은 ms, duty는 8비트 PWM 값(1~255)이다. `96`은 약 38% 듀티이며 전압·진동 강도·전류의 직접 측정값이 아니다.

| 명령 | 동작 |
|---|---|
| `help` | 명령 목록 |
| `status` | 모드·PWM 초기화·arm·남은 시간·5채널 논리 세기·힙 출력 |
| `mode dry` | 모터 OFF, DRY_RUN 전환 |
| `mode motors` | 모터 OFF, 실제 출력 모드 전환. **이 명령만으로 구동하지 않음.** |
| `arm` | 다음 pulse 한 번을 10초 이내 허용 |
| `pulse TH 96 300` | TH만 96/255 듀티로 300ms 구동 |
| `pulse TH,IN 96 300` | TH·IN 동시 구동. 쉼표 주변에 공백을 넣지 않음. |
| `pulse ALL 96 300` | 다섯 채널 동시 구동 |
| `stop` | 모든 출력 OFF, arm 해제 |
| `!` | 줄바꿈 없이 정지 요청 처리. 이후 새 줄로 입력을 다시 시작. |
| `scan` | 모터 OFF·arm 해제 후 GPIO6/7 I²C 주소 검사 |
| `imu` | 모터 OFF·arm 해제 후 주소 0x68의 WHO_AM_I, 센서 원시값 1회 검사 |

### 1. 외부 모터 전원 없이 명령만 확인

아래 명령을 **한 줄씩** 입력한다. `pulse` 후 300ms 이상 기다리고 `status`로 OFF를 확인한다.

```text
status
mode dry
arm
pulse TH 96 300
status
```

부팅 기본값은 `DRY_RUN`이다. DRY_RUN에서는 5개 모터 GPIO의 PWM duty가 실제로 0이며, 내장 LED는 논리 출력의 활성 여부만 표시한다. LED·로그 성공만으로 모터 배선이나 모터 동작이 확인되는 것은 아니다.

### 2. 검사한 모터 한 개를 실제 구동

무전원 검사와 USB 부팅을 통과한 다음 외부 DC 전원을 연결하고:

```text
mode motors
arm
pulse TH 96 300
```

실제 모터가 멈춘 뒤 `status`를 입력한다. 다음 시험마다 `arm`을 다시 입력한다. 낮은 duty에서 기동하지 않으면 단락·배선·전원 CC 상태를 확인한다. 전압을 올리기보다 확인된 3V에서 duty를 160, 필요 시 255로 올려 짧게 비교한다. 자동 기동 부스트는 구현하지 않았다.

검지 예:

```text
arm
pulse IN 96 300
```

다른 채널은 `MI`, `RI`, `PI`로 바꾼다. 채널별 검사를 통과한 뒤에만 `TH,IN`, `ALL`을 시험한다. 여러 명령을 한꺼번에 붙여 넣으면 진행 중인 pulse에서 다음 arm/pulse가 거절되고 OFF로 돌아갈 수 있으므로 한 시험씩 진행한다.

### 3. 정지·잘못된 명령·재부팅 확인

- `arm` → `pulse TH 96 1000` → 동작 중 `!`: 자동 만료 전에 실제 모터가 멈추는지 확인한다.
- `arm` → 10초 이상 대기 → `pulse TH 96 300`: 거절되며 모터가 움직이지 않아야 한다.
- `arm` → `pulse TH 999 300`: 오류, OFF, arm 해제. 다시 `arm`해야 한다.
- 실행 중 RESET: 모터가 멈추고 재부팅 후 DRY_RUN이어야 한다. **부팅 이전 OFF는 외부 10kΩ 풀다운과 실물 배선으로 확인해야 한다.**
- 시리얼 모니터 닫기·USB 분리 시 정지를 확인한다. USB CDC가 연결 해제를 알리지 않는 환경에서도 pulse는 지정 시간에 만료한다. 연결 감지는 OS·IDE별로 다를 수 있다.

### 4. IMU는 전압 확인 후 선택적으로

GY-521 VCC 입력 조건, 레귤레이터, SDA/SCL HIGH 전압을 확인한 뒤에만 `scan`, `imu`를 실행한다. 센서가 무전원인 상태에서는 두 명령을 실행하지 않는다. USB 단독 단계에서는 I²C를 자동으로 초기화하지 않는다.

AD0=GND이면 `scan`에서 주소 `0x68`, `imu`에서 `WHO_AM_I=0x68`과 RAW ax/ay/az/temp/gx/gy/gz를 기대한다. `imu`는 잠자기를 해제하고 원시값 한 번을 읽는다. 모터를 끈 상태로만 시험하며 자세 추정·교정·지속 스트리밍 기능은 없다. 이 코드는 MPU6050을 대상으로 하므로 다른 호환 칩의 식별값은 오류로 표시한다.

모터 초기 시험의 3V 레일에서는 GY-521 레귤레이터 출력이 부족할 수 있다. 이때 IMU 오류만으로 고장 판정하지 말고 모듈 입력 조건·실제 레귤레이터 출력부터 확인한다.

## 출력 제한과 실패 처리

- pulse 시간은 **1~1000ms**, arm은 10초, pulse 한 번에 arm을 소비한다. 계속 ON·자동 순차 구동은 없다.
- pulse 진행 중 다시 arm/pulse를 보내면 진행 중 출력을 끄고 거절한다. `status`·`help`는 진행 중 pulse를 연장하지 않는다.
- 모드 변경, stop, I²C 검사, 잘못된 명령, 너무 긴 입력(79자 초과), 제어 문자, 미완성 입력 1초 정체는 OFF·arm 해제로 처리한다.
- USB 연결 감지는 보조 신호다. 감지 값이 500ms 연속 false이고 새 입력도 없으면 정지한다. 미완성 입력이 있었을 때만 그 줄의 나머지를 폐기하므로 정상적인 첫 새 명령은 바로 처리한다. 폐기 중인 미완성 입력이 있으면 **빈 줄을 보내고** 다시 입력한다. 연결 해제를 놓치더라도 pulse 시간 제한이 적용된다.
- `Serial`의 연결 감지 값으로 입력을 차단하지 않는다. 실제 수신 바이트가 있으면 그 값을 읽는다. ESP32-C3 HWCDC의 순간적인 false 감지가 정상 명령을 차단·폐기하는 문제를 피하기 위한 변경이다.
- FreeRTOS 출력 작업은 약 5ms 주기로 만료를 검사한다. Serial 로그·I²C 접근은 출력 mutex 밖에서 수행하므로 출력 작업이 로그나 센서 응답을 기다리지 않는다.
- `!`는 시리얼 입력 루프가 해당 바이트를 읽을 때 처리하므로 USB 전달·스케줄링·시리얼 로그 지연이 있을 수 있다. pulse 자체의 시간 만료는 별도 출력 작업에서 처리한다. 물리 전원 차단을 대신하는 비상 정지 장치는 아니다.
- PWM 설정/쓰기 실패 시 PWM 연결을 해제하고 GPIO를 LOW로 돌린다. 실제 모터 모드는 차단하며 `pwm=FAULT`로 확인한다.
- 위 시간은 스케줄링 지연을 포함하는 하드 실시간 보장이 아니다. 소프트웨어 오류, MOSFET 고장, 모터·전원 단락은 별도 전원 차단으로 대응해야 한다. 이 코드는 전류·온도·배터리 전압을 측정하지 않으며 반복 구동의 총시간이나 과열을 제한하지 않는다.

## PC에서 검사

하드웨어가 없는 PC/Linux에서 실제 사용되는 C++ 파서·상태기계·입력 프레이밍을 검사한다.

```bash
g++ -std=c++17 -Wall -Wextra -Werror tests/bench_test.cpp -o /tmp/kimgane-bench-test
/tmp/kimgane-bench-test
```

검사 내용: 채널 분리, 1~255 duty, 시간·arm 경계, 정지/오류 처리, 연속 pulse 거절, `millis()` 순환, CRLF·입력 넘침·즉시 정지·부분 입력·USB 재연결 시 입력 폐기. Arduino 컴파일 및 PC 검사가 실제 전원·PWM·진동 시험을 대신하지 않는다.

실제 `.ino`의 `setup`/`loop`/출력 작업을 호스트의 대체 API로 실행하는 회귀 검사도 있다. USB 드라이버·물리 회로·실제 스레드 스케줄링을 재현하는 검사는 아니다.

```bash
g++ -std=c++17 -Wall -Wextra -Werror -Itests/fakes tests/sketch_test.cpp -o /tmp/kimgane-sketch-test
/tmp/kimgane-sketch-test
```

2026-10-14 수정 버전: MSVC `/W4 /WX /analyze`에서 **17,750개 파서·상태·입력 검사와 실제 스케치 제어 흐름 23개 회귀 검사 통과**, Arduino-ESP32 3.3.11의 ESP32-C3/USB CDC 설정으로 경고 없이 컴파일했다. 프로그램 337,154바이트(25%), 정적 RAM 15,428바이트(4%)다. 이후 사용자 재업로드로 `status`, `pwm=OK`, 입력 카운터 증가를 확인했다.

같은 날 TH 시험에서 과전류가 발생했고, 모터를 분리해도 전력이 증가했다. 사용자 다이오드 검사에서 역방향 도통 패턴을 확인하고 **TH 보호 다이오드 D2를 반전 재실장한 뒤 실제 모터 동작과 약 0.05A(50mA)를 확인**했다. 최종 시험의 전압·duty·시간 및 나머지 4채널·5개 동시 구동·IMU·BLE 결과는 미확인이다. 상세 경과는 [실기 점검 기록 11장](../../../docs/2026-10-14_DH_PCB_조립후_ESP_동작점검.md#11-th-과전류-진단과-다이오드-수리-결과)에 있다.
