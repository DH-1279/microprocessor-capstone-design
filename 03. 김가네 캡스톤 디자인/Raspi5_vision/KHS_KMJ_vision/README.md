# 통합 영상·음성 실행기

`Raspi5_vision` 폴더에서 가상환경을 활성화한다. 음성을 처음 준비할 때는 detector를 종료한 상태에서 실행한다.

```bash
source .venv/bin/activate
python -u -m KHS_KMJ_vision.prepare_audio
python -m KHS_KMJ_vision.prepare_audio --check
```

첫 명령은 Supertonic으로 고정 안내와 물체별 안내를 합성해 `~/.cache/kimgane-haptic/tts`에 저장한다. 마이크·카메라·BLE를 열거나 소리를 재생하지 않는다. 첫 실행 시 기존 Supertonic 모델 다운로드에 네트워크가 필요할 수 있다. 다시 실행하면 정상 파일은 재사용하고 누락·손상된 파일만 만든다. `--check`는 파일 검사만 하며 준비할 파일이 있으면 종료 코드 1을 반환한다. `--list`는 문장 목록만 표시한다.

물체 선택 안내는 **물체별 한 문장 + 공통 방향 설명**을 한 묶음으로 재생한다. 중간에 준비음이 끼어들지 않으며, 안내가 끝난 뒤 준비음이 한 번 울린다. 물체 목록처럼 조합이 달라지는 문장은 처음 요청할 때 합성하고 이후 캐시를 재사용한다. 따라서 모든 상황의 실시간 합성이 없어지는 것은 아니다.

```bash
export DISPLAY=:0
python -u KHS_KMJ_vision/detector.py \
  --address 9C:CC:01:82:75:8A \
  --mode 3 --reach-px 75 --reach-frames 8
```

`voice_profile.py`에서 실행기와 사전 생성기가 같은 물체 목록·음성·캐시 설정을 사용한다. 준비음 기본값은 880Hz, **250ms, 진폭 6,000**이다. QA 요청에 따라 길이는 유지하고 파형 진폭을 기존 12,000의 절반으로 낮췄다. `ready_tone_ms`, `ready_tone_amplitude`를 조절하면 준비음 파일도 구분해 생성한다. 예전 80ms 준비음 파일은 재사용하지 않는다. 준비음이 끝난 뒤 짧은 잔향 대기를 거쳐 입력을 받는다. 실제 청감은 스피커와 시스템 볼륨에서도 확인해야 한다.

터미널의 `TTS 대기`, `TTS 합성`/`TTS 캐시`, `TTS 재생 요청` 로그로 지연 구간을 구분한다. 재생 요청은 `aplay`를 실행하기 직전이며 실제 스피커에서 소리가 시작된 시각을 측정한 값은 아니다. 기존 TTS 모델 로딩과 음성 인식 시간은 별도다.

ESP 펌웨어와 BLE 패킷 규격은 이번 변경으로 바뀌지 않는다.

## 11월 2일 QA: BLE 알림과 마이크 전원

실제 BLE가 연결되지 않았을 때는 입력 준비음을 억제하고 BLE 상태를 화면·로그로만 표시한다. 음성 명령 입력은 계속 가능하다. 연결·재연결 완료 시 기존 `caps=07` ESP에 전체 모터 duty 180, 200ms 한 번을 전송한다. 안내 좌표는 이 알림이 끝난 뒤 새 프레임으로 처리한다. `--dry-run`이나 ESP DRY_RUN에서는 실제 연결 진동을 내지 않으며, `--no-ble`·`--dry-run` 음성 시험에서는 준비음을 사용할 수 있다. `check_link`는 계속 STOP과 상태 읽기만 사용한다.

통합 실행기의 마이크 입력은 숫자 인덱스 대신 `arecord`와 `plughw:CARD=GM20U,DEV=0`을 사용한다. 마이크가 꺼져 있어도 앱을 시작하며, USB 입력이 종료되거나 PCM이 2초 이상 멈추면 녹음 프로세스를 닫고 2초 간격으로 다시 연다. 장치가 정상 PCM을 보내면 이전 입력·인식 결과를 무효화하고 새 입력을 준비한다. 마이크 스위치가 USB를 제거하지 않고 음소거만 하는 경우에는 무음 PCM을 정상 입력으로 취급한다. 무음이라는 이유만으로 재연결하지 않는다.

```bash
arecord -l
# card N: GM20U [...]가 보이는지 확인한다. N이 달라져도 CARD=GM20U로 연다.
```

`voice_profile.py`의 `input_alsa_device`가 실제 카드 ID와 일치해야 한다. 다른 녹음 프로그램이 장치를 점유하면 기다리며 재시도한다. 이 자동 복구는 `input_backend="alsa"`인 통합 실행기 설정에 적용된다. 기존 `sounddevice` 경로도 유지하지만 USB 자동 복구용 경로는 아니다.

스피커 재생·볼륨 설정은 `UACDemoV10`, 마이크 입력은 `GM20U`로 분리한다. 사용자 `aplay -l`에서 카드 2가 스피커 UACDemoV10이고 카드 3은 GM20U의 재생 단자임을 확인했다. 기존 `plughw:3,0` 출력을 `plughw:CARD=UACDemoV10,DEV=0`으로 고쳐 USB 재인식에 따른 카드 번호 변화에도 같은 스피커를 선택한다. 다른 스피커를 쓸 때는 `voice_profile.py`의 `speaker_card`를 변경한다.

시작 안내 문구는 준비음 유무에 의존하지 않도록 줄였다. 실제 GM20U 스위치 OFF/ON과 장갑 연결 시험은 별도로 확인해야 한다.

## 시동어·목표 선택 대기 중 물건 목록 유지

대기 중 물건은 최근 5개 유효 프레임에서 3번 확인하면 목록에 등록하고, 마지막 실제 관측 후 3초까지 유지한다. 짧게 손이 가리거나 탐지가 빠져도 TTS·상단 목록에서 바로 삭제하지 않는다. 잠깐 사라진 물건의 마지막 박스는 `[LIST HOLD]` 점선으로 표시해 현재 탐지와 구분한다. 읽기 시작한 목록은 하나의 문장으로 고정하며 도중 프레임으로 바꾸지 않는다.

목록에 남은 물건을 선택했지만 현재 프레임에서 안 보이면 최대 2초간 새 탐지를 기다린다. 현재의 유효한 프레임에서 해당 물건을 확인해야 안내를 시작하고, 확인하지 못하면 목표 선택 대기에 머문다. 취소·다른 목표 입력은 기존 선택 대기를 지우거나 교체한다. 목록 유지용 좌표를 새 제어 관측으로 사용하지 않는다.

추가 옵션은 `--list-hold 3 --list-window 5 --list-hits 3 --selection-wait 2`이며 생략하면 이 값이 적용된다. 손을 올릴 때의 문제는 사용자의 확인에 따라 **목표 선택 전 목록 안정화**로 처리했다. 목표 선택 후 잠금·손 상실 시 정지·손바닥 획득 판정·mode 3 진동·완료 알림은 기존 동작을 유지한다. 실제 인식 모델 자체가 가려진 물건을 계속 검출하는 기능은 아니다.

자세한 변경과 시험은 [대기 중 물건 목록 안정화](../../docs/2026-11-02_DH_QA_대기중_물건목록_안정화.md)를 참고한다.
