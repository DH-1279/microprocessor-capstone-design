# USB 마이크·스피커 수령 및 라즈베리파이 동작 점검

- 작업일: 2026-10-15
- 담당: 김동환(DH)
- 대상: Raspberry Pi 5에 연결한 USB 마이크와 USB 스피커
- 목적: 음성 인터페이스 개발 전에 실제 장치 인식·녹음·재생이 가능한지 확인
- 확인 근거: 사용자가 전달한 라즈베리파이 터미널 출력과 실제 청취 결과

**USB 마이크와 스피커를 인식했으며, 5초 녹음 후 스피커로 재생하는 기본 입출력 시험을 사용자 확인으로 완료했다.** 이번에는 ALSA 명령으로 장치만 점검했다. 프로젝트 STT·TTS·호출어·영상·BLE 통합을 실행한 것은 아니다.

## 1. 연결 장치와 최종 인식 결과

| 구분 | 장치 이름 | ALSA 카드·장치 | 확인 결과 |
|---|---|---|---|
| USB 스피커 출력 | `UACDemoV10` / 표시명 `UACDemoV1.0` | card 2, device 0 | 테스트 음성 및 녹음 파일 재생 확인 |
| USB 마이크 입력 | `GM20U` | card 3, device 0 | 녹음 및 녹음 음성 청취 확인 |
| 마이크 장치의 재생 인터페이스 | `GM20U` | card 3, device 0 | 목록에 표시됨. 이번 스피커 재생 시험에는 사용하지 않음 |

HDMI 출력은 card 0과 card 1로 표시됐다. 시험에서는 USB 스피커인 card 2를 명시적으로 선택했다.

### 장치 조회 명령

라즈베리파이 터미널에서 실행했다. ALSA 명령을 사용하는 이 시험에는 Python 가상환경이 필요하지 않다.

```bash
lsusb
arecord -l
aplay -l
```

최종 USB 목록에서 확인한 장치는 다음과 같다.

```text
ID 4c4a:4155 Jieli Technology UACDemoV1.0
ID 0000:0000 GM20U GM20U
```

최종 녹음 목록에는 `card 3: GM20U`, 재생 목록에는 HDMI 두 장치와 `card 2: UACDemoV10`, `card 3: GM20U`가 표시됐다. USB 목록에 나타난 사실과 실제 녹음·재생 가능 여부는 구분해서 확인했다.

## 2. 최초 상태와 확인 과정

### 마이크가 처음에는 녹음 목록에 없었음

첫 출력에는 USB 스피커만 있었고 `arecord -l`의 녹음 장치 목록이 비어 있었다. 이 상태에서는 마이크 녹음을 시험할 수 없었다.

마이크를 다른 USB 포트에 직접 다시 연결하도록 안내한 뒤, 사용자가 보낸 다음 출력에서 GM20U가 USB 목록과 녹음 목록에 나타났다. 최초 미인식의 정확한 원인은 확정하지 않았다. 드라이버 설치나 설정 파일 변경으로 해결했다고 기록하지 않는다.

### 스피커는 재생됐지만 음량이 작았음

다음 명령으로 스피커를 시험했고 사용자가 소리가 난다고 확인했다.

```bash
speaker-test -D plughw:2,0 -c 2 -t wav -l 1
```

사용자는 최초 시험에서 소리가 너무 작다고 보고했다. 스피커 자체 볼륨과 아래 ALSA 믹서 확인 방법을 안내했다.

```bash
alsamixer -c 2
# 조절 항목을 확인해야 할 때
amixer -c 2 scontrols
```

믹서에서는 F3로 재생 항목을 보고, 방향키로 볼륨을 조절하고, `MM` 표시가 있으면 M으로 음소거를 해제하도록 안내했다. **실제 적용한 볼륨 값과 믹서 출력은 전달되지 않았다.** 이후 녹음·재생 성공은 확인했지만, 최종 음량이나 음질을 수치로 검증한 것은 아니다.

## 3. 마이크 5초 녹음과 USB 스피커 재생

### 녹음

```bash
arecord -D plughw:3,0 -f S16_LE -r 16000 -c 1 -d 5 -t wav /tmp/mic-test.wav -vv
```

- 입력: card 3, device 0의 GM20U.
- 형식: 16-bit signed little-endian, 16kHz, 모노, WAV.
- 길이: 5초.
- 파일: 라즈베리파이의 `/tmp/mic-test.wav`.
- `-vv`로 입력 레벨 표시를 확인하도록 안내했다. 레벨 수치나 화면은 따로 전달되지 않았다.

### 재생

```bash
aplay -D plughw:2,0 /tmp/mic-test.wav
```

녹음 파일을 card 2의 USB 스피커로 재생한 뒤 사용자가 **“잘됨”**이라고 확인했다. 이 결과로 실제 마이크 녹음과 스피커 재생의 기본 경로를 확인했다.

`/tmp`의 녹음 파일은 임시 시험용이며 저장소에 추가하지 않았다. 명령 사용 근거는 [ALSA 공식 사운드카드 테스트 안내](https://alsa-project.org/wiki/SoundcardTesting)를 참고한다.

## 5. 다음 개발 시 적용할 사항

1. 카드 2와 3은 **이번 ALSA 조회의 번호**다. 재부팅·재연결 후 달라질 수 있으므로 실제 목록을 다시 확인하고, 가능한 경우 장치 이름으로 선택한다.
2. ALSA 카드 번호와 Python `sounddevice`의 장치 인덱스는 동일하다고 가정하지 않는다. Python 장치 목록에서 이름·입력/출력 채널을 확인한 뒤 프로젝트에 연결한다.
3. 이번 결과는 Linux 기본 녹음·재생 성공이다. Whisper·TTS 엔진·Python 오디오 패키지의 설치나 동작까지 확인된 것으로 확대하지 않는다.
4. 다음 시험은 한국어 TTS 한 문장 재생과 STT 명령 인식을 각각 확인한 뒤 연결하는 순서로 진행한다. 팀원 코드 수정 사항은 [15일 코드 리뷰 문서](2026-10-15_DH_팀원코드리뷰_및_실행점검.md)를 따른다.
