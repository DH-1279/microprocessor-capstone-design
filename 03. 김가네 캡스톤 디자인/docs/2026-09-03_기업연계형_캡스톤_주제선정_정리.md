# 기업연계형 캡스톤디자인 주제 선정 정리

작성 기준일: 2026-09-03

내일 결정·논의용: 2026-09-04(금)

## 1. 최종 선정 주제

### 국문

**Jetson Nano와 Raspberry Pi 5 기반 Edge AI 제조부품 외관 불량 검사 및 자동 분류 시스템**

### 영문

**Edge AI-Based Visual Defect Inspection and Automated Sorting System Using Jetson Nano and Raspberry Pi 5**

### 한 문장 설명

> 참여기업의 실제 부품 또는 포장제품을 카메라로 촬영하고, Jetson Nano가 스크래치·누락·오조립·형상 이상을 실시간 판정하며, Raspberry Pi 5가 생산 흐름 제어·불량품 분류·검사기록·대시보드를 담당하는 인터넷 비의존형 품질검사 시제품이다.

### 이 주제를 최종 추천하는 이유

1. **기업 수요가 명확하다.** 제조기업은 육안검사의 편차, 검사인력 부담, 불량품 유출과 검사기록 부족을 실제 문제로 제시할 수 있다.
2. **학술제 시연성이 높다.** 카메라 앞을 지나가는 부품을 AI가 판정하고 서보모터가 불량품을 자동 분리하는 장면을 즉시 보여줄 수 있다.
3. **수치 평가가 가능하다.** precision, recall, F1-score, mAP, 정상 오검출률, 불량 미검출률, FPS, 지연시간, 자동분류 성공률을 제시할 수 있다.
4. **두 보드의 역할이 분명하다.** Jetson Nano는 GPU 기반 AI 추론, Raspberry Pi 5는 장치 제어·검사 이력·대시보드를 담당한다.
5. **기업 제품에 맞게 변형하기 쉽다.** 플라스틱 사출품, 자동차부품, 포장제품, 조립품, PCB, 라벨 등 확보 가능한 대상을 그대로 적용할 수 있다.

## 2. 전체 시스템 구성

```text
광전센서/버튼 ──> Raspberry Pi 5 ── 촬영 명령 ──> Jetson Nano 4GB
                        │                              │
                        │                        카메라 영상
                        │                        AI 불량 판정
                        │                              │
                        <──── 판정 결과/신뢰도/좌표 ────┘
                        │
              ┌─────────┼──────────┐
              │         │          │
          서보 분류기  경광등/부저  검사 DB·웹 대시보드
```

### Jetson Nano 4GB의 역할

- USB 또는 CSI 카메라 영상 입력
- 이미지 전처리와 관심영역 추출
- 경량 객체탐지 또는 이상탐지 모델 추론
- 정상/불량, 불량 종류, 신뢰도와 위치 반환
- TensorRT 또는 경량화 모델을 이용한 추론속도 최적화

### Raspberry Pi 5의 역할

- 광전센서 입력과 검사 순서 관리
- Jetson Nano에 촬영·판정 요청
- 서보모터 또는 솔레노이드 분류기 제어
- 정상/불량 수량, 판정시간, 이미지와 로그 저장
- 로컬 웹 대시보드와 관리자 화면 제공
- Jetson 응답 지연·통신단절·카메라 오류 감시

### 선택 구성

- 저속 전시용 컨베이어 또는 회전 테이블
- 조명 박스와 확산판
- 광전센서 또는 근접센서
- 서보모터 분류 게이트
- 경광등·부저·비상정지 버튼
- 3D 프린팅 카메라 지지대, 케이스, 분류 슈트
- INA219 등 전력센서를 이용한 보드별 소비전력 측정

Linux SBC의 GPIO는 엄격한 실시간 제어에 한계가 있으므로 전시용 저속 장치는 Raspberry Pi 5로 제어하되, 모터 타이밍이 불안정하면 ATmega328P 또는 별도 PWM 드라이버를 보조 제어기로 추가한다. 핵심 주제는 Edge AI 검사이며, 보조 MCU는 반드시 필요한 경우에만 넣는다.

## 3. 검사 대상 선정

기업을 먼저 정한 뒤 해당 기업이 제공할 수 있는 실제 부품을 선택한다. 우선순위는 다음과 같다.

1. **플라스틱 사출품:** 스크래치, 찍힘, 미성형, 버(burr), 색상 이상
2. **조립부품:** 나사·클립·고무패킹 누락, 방향 오류, 오조립
3. **포장제품:** 라벨 누락·기울어짐, 밀봉 불량, 구성품 누락
4. **자동차·기계부품:** 홀 위치, 체결부 누락, 표면 오염과 형상 이상
5. **PCB:** 부품 누락·방향 오류·납땜 외관 이상. 단, 미세 불량은 광학계와 데이터 확보 난도가 높아 후순위로 둔다.

내일은 구체적인 제품을 임의로 확정하지 말고, 기업이 정상품과 불량품 또는 불량 재현 방법을 제공할 수 있는지를 먼저 확인한다. **데이터를 확보할 수 있는 제품이 가장 좋은 제품**이다.

## 4. AI 범위와 학술제 연구 질문

### 권장 AI 방식

- 불량 위치 표시가 필요한 경우: 경량 객체탐지 모델
- 정상 샘플은 많지만 불량 샘플이 적은 경우: 이상탐지 모델
- 제품 전체의 정상/불량만 구분하면 되는 경우: 경량 이미지 분류 모델

Jetson Nano에서는 학습하지 않고, 기존 PC나 학교 GPU·무료 환경에서 모델을 학습한 뒤 Jetson에 배포한다. LLM은 전혀 필요하지 않다.

### 핵심 연구 질문

> 제한된 연산자원을 가진 Jetson Nano에서 경량화·TensorRT 최적화를 적용했을 때 검사 정확도를 유지하면서 실시간 처리속도와 전력 효율을 얼마나 개선할 수 있으며, Raspberry Pi 5 단독 추론과 비교했을 때 어떤 배치 구조가 소규모 제조현장에 가장 적합한가?

### 비교실험

동일한 테스트 이미지와 동일한 입력 해상도로 다음 구성을 비교한다.

1. Raspberry Pi 5 CPU 단독 추론
2. Jetson Nano 기본 모델 추론
3. Jetson Nano 경량화·TensorRT 최적화 추론

측정항목:

- 정상/불량 precision, recall, F1-score
- 불량 미검출률(False Accept)과 정상 오검출률(False Reject)
- 평균·95백분위 추론 지연시간
- 초당 처리 프레임(FPS)
- 전력소모와 1개 검사당 에너지
- 카메라 촬영부터 분류기 작동까지 전체 지연시간
- 서보 분류 성공률
- 조명 밝기·각도 변화에 따른 성능 저하

### 성공기준 예시

- 불량 recall 90% 이상
- 정상 오검출률 5% 이하
- 전체 판정 및 분류 지연 1초 이하
- 자동분류 성공률 95% 이상
- 인터넷이 끊겨도 검사와 분류가 계속 동작

수치는 예비실험과 기업의 요구수준을 반영해 9월 말에 최종 확정한다. 안전·인증 장비가 아닌 교육용 개념검증임을 명확히 한다.

## 5. 데이터 수집 계획

- 정상품 300장 이상
- 불량 유형별 150장 이상을 목표로 수집
- 각 부품을 여러 방향·위치·밝기에서 촬영
- 학습/검증/시험 데이터는 동일 사진의 중복이 없도록 분리
- 최종 시험 세트는 모델 조정에 사용하지 않음
- 기업 제품명·도면·생산정보가 노출되는 경우 비식별화와 공개 범위를 협약서에서 결정
- 불량품 확보가 어렵다면 기업과 협의한 재현 가능한 결함만 사용하고 실제 불량처럼 표현하지 않음

정확도만 높이기 위해 거의 같은 연속 사진을 학습·시험 데이터에 나누어 넣으면 데이터 누수가 발생한다. 가능하면 촬영 회차 또는 실제 부품 개체 단위로 데이터를 분리한다.

## 6. 기업에 요청할 실질 역할

1. 검사 대상 제품 1종과 핵심 불량 유형 2~3종 정의
2. 정상·불량 판정 기준과 허용오차 제공
3. 정상품·불량품 또는 안전한 불량 재현 방법 제공
4. 조명, 촬영방향, 검사속도와 설치공간 요구사항 검토
5. 10월 설계검토와 11월 중간 시연 참여
6. 최종 시제품의 미검출·오검출·설치편의성 평가
7. 결과 이미지와 기업명 공개 범위 승인

기업 수요내용 예시:

> 당사는 [제품명]의 외관 및 조립상태를 작업자가 육안으로 검사하고 있으나 검사자의 숙련도와 작업환경에 따라 판정 편차가 발생하며, 검사결과가 자동으로 기록되지 않아 불량 원인과 발생 추이를 분석하기 어렵다. 고가의 상용 비전검사 장비 대신 기존 공정 옆에 설치할 수 있고 인터넷 연결 없이 정상 여부와 [스크래치/부품 누락/오조립]을 판정하며 불량품을 자동 분리하는 저비용 시제품을 요청한다. 특히 조명과 제품 위치가 변하는 상황에서도 불량 미검출과 정상 오검출을 줄이고, 검사결과와 이미지를 로컬에서 조회할 수 있어야 한다.

### Jetson과 Raspberry Pi 구매비의 중요 확인사항

수업 설명자료에서는 고품질 작품을 위해 Raspberry Pi 5까지 고려할 수 있다고 안내하지만, 학생용 온라인 가이드의 집행불가 목록에는 PC·PC 관련 부품과 완제품이 포함되어 있다. 따라서 **Jetson Nano와 Raspberry Pi 5의 구매비가 재료비로 인정된다고 단정할 수 없다.**

- 이미 보유한 보드는 현물로 사용하고 지원금은 카메라, 조명, 센서, 모터, 기구물과 제작재료에 쓰는 방안이 가장 안전하다.
- 새로 구매해야 한다면 모델명, 가격, 시제품에서의 역할을 적어 교수님과 사업단에 사전 서면 확인을 받는다.
- 승인 전에는 보드, 전원어댑터, microSD, SSD, 저장장치를 결제하지 않는다.

### 제공 서식의 오류

폴더명과 안내는 2026학년도 2학기용이지만 산학연계교육 운영 협약서 본문에는 “2026학년도 1학기”가 남아 있다. 기업 서명 전에 교수님 또는 사업단에 2학기로 수정할지 반드시 확인한다.

## 11. 신청서 250자 이상 초안

### 과제의 목적 및 필요성

중소 제조현장에서는 제품의 스크래치, 부품 누락, 오조립과 같은 외관 불량을 작업자가 육안으로 검사하는 경우가 많다. 육안검사는 작업자의 숙련도와 피로도, 조명과 검사속도에 따라 결과가 달라질 수 있으며 검사 이미지와 판정 결과가 자동 축적되지 않아 불량 발생 원인을 추적하기도 어렵다. 본 과제는 [참여기업명]의 [제품명] 검사 수요를 바탕으로 Jetson Nano와 Raspberry Pi 5를 이용한 저비용 Edge AI 외관검사 및 자동분류 시제품을 개발하는 것을 목적으로 한다. 인터넷이나 유료 클라우드에 의존하지 않고 현장에서 영상을 분석해 정상·불량과 불량 유형을 판정하고, 불량품을 자동 분리하며 검사 이력을 저장함으로써 소규모 공정에도 적용 가능한 품질관리 방법을 검증하고자 한다.

### 과제 수행 방법 및 결과물 개발 계획

먼저 참여기업과 협의하여 검사 대상 제품 한 종류와 스크래치, 구성품 누락, 방향 오류 등 핵심 불량 유형 2~3가지를 정하고 정상·불량 판정 기준과 공개 가능한 데이터 범위를 확정한다. 고정된 카메라와 조명 박스에서 제품을 여러 위치·각도·밝기로 촬영해 학습·검증·최종시험 데이터를 분리하여 구축한다. 경량 객체탐지, 이미지 분류 또는 이상탐지 모델 중 데이터 특성에 맞는 방식을 선택해 학습하고 Jetson Nano에 배포한다. Raspberry Pi 5는 광전센서, 제품 이송, Jetson과의 통신, 서보 분류기, 검사기록과 로컬 대시보드를 담당한다. 동일한 시험데이터로 Raspberry Pi 5 단독 추론, Jetson 기본 추론, TensorRT 최적화 추론을 비교하고 정확도, 미검출률, 오검출률, FPS, 지연시간과 소비전력을 평가한다.

### 기대효과 및 활용방안

본 과제를 통해 고가의 상용 비전검사 장비를 도입하기 어려운 기업이 특정 부품이나 포장공정에 적용할 수 있는 저비용 Edge AI 품질검사의 가능성을 확인할 수 있다. 불량 판정이 인터넷과 외부 서버 없이 현장에서 수행되므로 통신장애 상황에서도 검사를 지속할 수 있고, 제품 이미지와 판정시간, 불량 유형이 자동 저장되어 불량 발생 추이를 분석할 수 있다. 참여기업은 실제 판정 기준을 이용한 미검출률과 오검출률, 설치공간, 조명 민감도와 처리속도를 확인하고 후속 적용 여부를 판단할 수 있다. 향후에는 카메라 추가, 제품별 모델 전환, 공정관리 시스템 연동과 최신 Jetson 플랫폼 이전을 통해 여러 생산라인에서 사용하는 모듈형 검사장치로 확장할 수 있다.

[참여기업명]은 과제 초기에 실제 검사 대상인 [제품명]과 핵심 불량 유형, 허용오차, 현재 육안검사의 문제점과 요구 검사속도를 제시하고 정상품·불량품 또는 안전한 결함 재현 방법을 제공한다. 학생팀은 기업의 요구사항에 따라 카메라와 조명, AI 모델, 자동분류 기구, 검사기록 화면을 설계하고 지도교수의 검토를 받아 구현한다. 기업 담당자는 10월 설계검토에서 촬영방향과 판정 기준, 설치 편의성을 평가하고 11월 중간 시연에서 불량 미검출과 정상 오검출 사례에 대한 개선 의견을 제공한다. 12월에는 최종 시험결과와 시제품을 공동 검토해 실제 공정 적용 가능성과 추가 요구사항을 정리한다. 인터뷰, 회의록, 설계검토서, 시연사진과 최종평가서를 남겨 실질적인 산학협업 과정을 증빙한다.

## 14. 기술상 주의사항

- NVIDIA 공식 사양상 Jetson Nano는 128 CUDA core Maxwell GPU, quad-core Cortex-A57 CPU와 4GB LPDDR4를 제공해 경량 영상 추론에 사용할 수 있다.
- Jetson Nano Developer Kit은 EOL이고 Jetson Nano가 지원하는 마지막 JetPack 계열은 4.6.6이다. 최신 Python·PyTorch·YOLO 패키지를 그대로 설치하려 하면 호환성 문제가 생길 수 있으므로 **9월 첫 주에 모델 배포환경부터 확인**한다.
- Raspberry Pi 5는 2.4GHz quad-core Cortex-A76, 2개의 4-lane MIPI 카메라/디스플레이 인터페이스와 GPIO를 제공한다. 공식 권장은 5V/5A USB-C 전원이며 고성능 작업에는 능동냉각이 필요하다.
- 두 보드를 단순히 모두 넣는 것이 목적이 아니다. 동일 모델의 성능 비교 후 Jetson은 AI, Pi는 제어·기록으로 역할을 분리해야 설계 타당성이 생긴다.
- Jetson Nano는 구형 플랫폼이므로 결과보고서에는 교육용·기업 검증용 시제품이라고 명시하고, 상용화 후속안으로 Jetson Orin Nano 또는 최신 가속기로의 이전을 제안한다.

### 우리 과제에 가져올 부분

- Jetson Nano는 5V/4A 배럴 전원과 J48 점퍼를 사용해 고부하 시 전원 불안정을 줄인다. 단, 보드 리비전에 따라 커넥터 구성이 다를 수 있으므로 사용자 가이드를 확인한다.
- 성능 측정 시 `nvpmodel`의 10W/MAXN 모드와 `jetson_clocks` 사용 여부를 명시한다.
- GUI가 메모리 병목을 만들 때만 헤드리스 모드를 사용한다.
- PyTorch 모델을 ONNX로 변환하고 Jetson에서 TensorRT FP32·FP16 엔진을 비교한다.
- 카메라 입력부터 전처리, 추론, 후처리, Pi 통신, 서보 작동까지 단계별 지연시간을 측정한다.
- 단순 AI 구동이 아니라 메모리 사용량, 프레임 누락, 온도, 전력과 장애복구를 함께 기록한다.

### 그대로 적용하지 않을 부분

- **VIO 자율비행:** Pixhawk, RealSense, SLAM, ROS2, 비행안전까지 동시에 해결해야 하므로 한 학기 기업연계형 과제로는 실패 위험이 지나치게 높다.
- **의미론적 분할 30 FPS:** 모델·해상도·카메라·전처리에 따라 성능이 크게 달라진다. 30 FPS를 보장값으로 적지 않고 실제 측정 결과로 제시한다.
- **다중 카메라 DeepStream:** Jetson Nano에서 새 기능을 지원한 마지막 계열은 DeepStream 6.0.1과 JetPack 4.6.1 조합이다. 최신 DeepStream 8.x 문서를 Nano에 그대로 적용하지 않는다. 우리 과제는 우선 단일 카메라로 완성하고 시간이 남으면 두 번째 카메라를 추가한다.
- **ROS2 Humble 컨테이너:** 우리 외관검사 장치에는 ROS2가 필수가 아니다. 시스템 구조를 복잡하게 만들기 위한 도입은 피하고 Ethernet 기반 REST, MQTT 또는 단순 소켓 중 하나로 Jetson-Pi 통신을 구현한다.
- **16GB Swap 필수 주장:** Swap은 OOM 방지를 위한 보조수단이지 성능 향상 수단이 아니다. 먼저 모델·입력 해상도·프로세스 메모리를 줄이고 필요한 경우에만 제한적으로 사용한다.
- **NVMe SSD 사용:** 일반 Jetson Nano Developer Kit의 M.2 Key E는 무선카드용이다. 직접 NVMe 저장장치 사용을 전제로 예산을 짜지 않으며, 저장장치 구매는 집행불가 항목과도 충돌할 수 있다.
- **INT8 적용 불가 단정:** Nano에 Tensor Core와 DLA가 없다는 사실과 TensorRT 엔진 생성 가능 여부·속도이득 여부는 구분해야 한다. 계획서에는 절대적인 “불가능”이라고 적지 않고 실제 JetPack/TensorRT 환경에서 엔진 생성과 지연시간을 확인한다. 기본 비교는 FP32와 FP16으로 제한한다.
- **FP16 1.4~2배, OpenCV CUDA 10배 등의 수치:** 출처와 조건이 일정하지 않으므로 예상 성능으로 인용하지 않는다. 동일 영상·해상도·워밍업·반복 횟수로 직접 벤치마크한 값만 결과에 사용한다.
