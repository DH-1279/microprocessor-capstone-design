# 라즈베리 BLE 송신부 — 시동어 프로그램과의 연결

작성일: 2026-10-28 / 작성: DH

대상 브랜치: `KimGA_raspi/2026-10-27`

기준 규격: [2026-10-27_DH_ESP32_BLE_송수신규격.md](2026-10-27_DH_ESP32_BLE_송수신규격.md)

## 1. 이번 구현 범위

`Raspi5_vision/ble_sender/`에 별도 송신 프로그램을 추가했다. 해수가 수정 중인 `KHS_KMJ_vision`의 음성·영상 코드와 ESP 펌웨어는 이번 변경에서 수정하지 않는다. **송신부만 실행하면 영상 입력을 기다리며 정지한다. 아래 연결 코드를 영상 프로그램에 적용해야 카메라 기반 안내가 시작된다.**

사용자가 정한 음성 흐름은 다음과 같으며 해수 코드가 담당한다.

```text
프로그램 실행 → 시동어 대기
 → 프로그램 설명 + 현재 인식 물체 목록
 → 물건 이름 입력 대기 (물체 목록 약 3초 주기 반복)
 → 물체 락온 + 안내 음성 (목록 반복 중단)
 → 안내 진행 ┬ 취소 → 시동어 대기
             └ 목표 도달 → 안내 종료
```

위의 3초는 **물체 목록 안내 주기**다. BLE는 안내 중에만 약 100ms마다 새 번호를 보내며 별도로 동작한다. 이 송신부는 시동어 처리, 목록 발화, 목표 선택, 도달·집기 판정을 구현하지 않는다.

## 2. 연결 구조

```text
해수의 영상·음성 프로세스
  안내 중: 같은 프레임의 손 21점 + 락온한 목표 박스 + 원본 시각
  취소·도달·상실·대기: STOP
            ↓ VisionPublisher (Pi 내부 127.0.0.1:8766 UDP)
독립 BLE 송신 프로세스 ← 터미널 mode 2 / mode 3
  프레임 검증 → 방향·근접 구간 계산 → BLE v2 명령 갱신
            ↓ BLE
ESP32-C3: 패턴 생성 → 선택된 모터 PWM
```

두 프로세스는 **동일한 라즈베리파이**에서 실행한다. 송신부는 카메라·Hailo·마이크를 열지 않아 기존 프로그램과 장치 점유가 겹치지 않는다. UDP에는 영상이나 음성을 넣지 않으며, 이 포트를 외부 PC·스마트폰에 개방하지 않는다. 하나의 영상 프로세스만 관측을 보낸다.

## 3. 설치와 실행

라즈베리에서 다른 터미널을 열고 실행한다. 기존 브랜치를 사용하며 신규 날짜 브랜치를 만들 필요가 없다. `git status`에 팀원이 작업 중인 변경이 있으면 먼저 해당 변경을 보존한 후 갱신한다.

```bash
cd "$HOME/Desktop/kimGA_raspi/microprocessor-capstone-design"
git branch --show-current
git status --short
# 작업 브랜치가 KimGA_raspi/2026-10-27이고 보존할 변경을 처리한 상태에서:
git pull --ff-only origin KimGA_raspi/2026-10-27

cd "03. 김가네 캡스톤 디자인/Raspi5_vision"
source .venv/bin/activate
python -m pip install -r ble_sender/requirements.txt
python -m ble_sender --mode 2
```

위 `git pull`은 **현재 브랜치가 김가네 브랜치일 때** 실행한다. 기존 가상환경 위치와 현재 폴더가 다르면 `source /절대경로/.venv/bin/activate`로 활성화한 뒤 위 `Raspi5_vision` 폴더에서 `python -m ble_sender`를 실행하면 된다.

ESP에는 `esp32_device/ble_final/firmware/ble_final_receiver`가 올라가 있어야 한다. 기본 이름 `KIMGANE-HAPTIC-V2`와 서비스 UUID로 찾는다. 주소를 알면 `--address XX:XX:XX:XX:XX:XX`를 추가할 수 있다. BLE 검색이 안 되면 `bluetoothctl show`에서 어댑터 상태를 확인한다.

시작 시 `ESP DRY_RUN: 실제 모터 출력 없음`이면 ESP 스케치의 `DRY_RUN=true` 상태다. 실제 모터 구동에는 점검된 PCB에서 `false`로 업로드해야 한다. 송신부의 `--dry-run`은 **BLE 연결 자체를 하지 않는 별도 옵션**이다.

### 터미널에서 모드 변경

같은 송신부 터미널에 입력한다. ESP 시리얼 모니터에 입력하는 명령이 아니다.

| 명령 | 동작 |
|---|---|
| `mode 2` | 고정 손가락의 간격 안내 |
| `mode 3` | 방향별 손가락 + 근접 두 번 진동 |
| `status` | 송신부 상태와 ESP 상태 패킷 조회 |
| `stop` | 즉시 정지, 새 영상이 와도 정지 유지 |
| `resume` | 정지 해제, 이후의 새 프레임부터 안내 |
| `quit` 또는 Ctrl+C | STOP을 시도하고 연결 종료 |

서로 다른 모드로 바꿀 때 먼저 STOP을 전송하고 기존 좌표를 폐기한다. 이후 원본 촬영 시각이 모드 변경 시각보다 새로운 관측으로 안내를 다시 시작한다. 같은 모드를 다시 입력하면 패턴을 재시작하지 않는다. `stop` 상태에서 모드를 바꿔도 정지 잠금은 유지된다.

설정 예:

```bash
python -m ble_sender --mode 3 --duties 180 180 180 180 180
```

`--duties`는 TH/IN/MI/RI/PI 순서, 각각 1..255다. 거리별로 세기를 키우지 않고 모터별 보정값을 유지한다. duty와 실제 체감 세기는 정비례하지 않으므로 부착 후 보정한다. 기본값 180은 사용자 평가 전 시험값이다.

## 4. 해수가 연결할 최소 코드

`detector.py` 등 실행기의 기존 경로 설정 후 한 번 생성한다. `Raspi5_vision`이 import 경로에 있어야 한다. 현재 실행기는 이 경로를 이미 추가하고 있다.

```python
import uuid
from ble_sender import VisionPublisher

ble_output = VisionPublisher()
# 새로운 물체를 락온할 때마다 부여한다. 클래스 이름만 반복 사용하지 않는다.
lock_id = uuid.uuid4().hex
frame_id = 0
```

카메라에서 새 프레임을 읽을 때마다 `frame_id += 1` 한다. 번호는 취소·재시작 시 되돌리지 않는다. `captured_at`은 `CameraSource.read()`가 반환한 **촬영 시작 기준 `time.monotonic()` 시각**이다. 추론 종료나 송신 순간으로 바꾸지 않는다.

```python
# frame, captured_at = cam.read()
# frame_id += 1
# objects = detector.detect(frame)
# ... 이 프레임에서 손을 추적하고 락온한 목표를 선택 ...

if (state == "SEARCHING"
        and hand_observed_this_frame
        and found_target is not None):
    ble_output.publish(
        target_id=lock_id,
        frame_id=frame_id,
        captured_at=captured_at,
        size=(frame.shape[1], frame.shape[0]),  # 실제 width, height
        landmarks=selected_current_landmarks, # 같은 손의 이번 프레임 21점
        target_box=found_target.box,          # normalized x1,y1,x2,y2
    )
else:
    ble_output.stop()
```

`hand_observed_this_frame`, `selected_current_landmarks`는 **연결자가 추적 결과에서 마련할 값**이며 현재 실행기에 이미 존재하는 변수라고 가정하지 않는다. MediaPipe 포인트 객체나 정규화된 `(x,y)` 21개를 넘길 수 있다.

필수 연결 조건:

1. 물체는 이번 프레임에서 실제 검출된 `found_target.box`를 넘긴다. 가려져도 보존하는 `locked_target_box`를 새 관측처럼 보내지 않는다.
2. 손의 유효성·신뢰도 검사와 같은 손의 랜드마크 선택이 먼저다. 현재 `tracker.last_landmarks`는 첫 번째 raw 손을 담을 수 있으므로 **유효한 선택 손과 동일한 손인지 확인하지 않은 채 연결하면 안 된다.** `hand_result`가 안정화 때문에 이전 값을 유지한 경우도 새 관측이 아니다. 손이 두 개여서 대응이 불명확하면 STOP한다.
3. 물체/손은 동일한 `frame_id`·촬영 시각·좌표계의 결과여야 한다. 별도 스레드에서 지난 손과 새 물체를 합치지 않는다.
4. 글러브는 왼손이며 추적기의 `hand="Any"`를 유지할 수 있다. 송신부는 MediaPipe의 Left/Right 라벨을 필터로 사용하지 않는다. 원본 좌표의 손 관절 축으로 방향을 계산한다. 손등 표시 등에 `worn_hand`가 필요하면 물리적 착용 손인 `"Left"`를 사용한다.
5. 화면 미리보기만 반전하면 원본 좌표를 유지한다. 추론 입력 자체가 반전되었을 때만 송신부에 `--mirrored`를 지정한다.

취소, 도달 판단, 시동어 대기/목표 이름 대기 진입, 손/목표 상실은 **그 분기에서 `continue`하기 전에** 정지한다. 프로그램 예외·종료에도 닫는다.

```python
# 취소 / 도달 / 대기 복귀 분기
ble_output.stop()
# 기존 음성 상태 전환 및 안내 ...

# 기존 실행기의 가장 바깥 finally에 추가
ble_output.close()
```

음성 상태의 이름을 바꿔도 ‘실제 안내 중에만 publish, 나머지는 stop’이라는 경계만 유지하면 된다. 목표를 다시 락온하거나 다른 인스턴스로 바꾸면 `lock_id`를 새로 발급한다.

## 5. 좌표 → 두 모드의 의미

### 2안: 고정 검지 + 진동 간격

기본 채널 IN(검지)로 고정한다. 검지 끝에서 목표 박스까지 영상 평면상 최단 거리를 구하고, 관측된 손바닥 폭으로 나눈다. 멀 때는 200ms ON/1000ms OFF, 중간은 200/500ms, 가까우면 200/200ms로 ESP가 반복한다. 손을 뒤집어도 검지 채널은 바꾸지 않는다. 다른 손가락 비교 시험은 시작 옵션 `--rate-channel TH` 등으로 지정한다.

### 3안: 손 기준 방향 + 근접 이벤트

손바닥 중심에서 목표 박스 중심을 향한 벡터를 손 관절 축으로 변환한다. 좌표의 가로/세로 비율을 보정하고, 손을 회전해도 엄지/소지/손끝/손목 기준 방향을 구한다.

| 방향 | 채널 |
|---|---|
| 엄지 쪽 | TH(엄지) |
| 소지 쪽 | PI(소지) |
| 손끝 쪽 | IN(검지) |
| 손목 쪽 | RI(약지) |
| 영상상 근접 | MI(중지), 두 번 진동 후 OFF |

근접 구간은 손바닥 중심에서 목표 박스까지의 영상 평면상 최단 거리를 손바닥 폭으로 나눈 값이다. 동일한 물체가 화면 같은 쪽에 있어도 손을 뒤집어 관절 축이 바뀌면 TH↔PI 등의 채널이 달라질 수 있다. ESP가 뒤집힘을 판단하지 않는다.

기본 근접 경계 `near=0.35`, 중간 경계 `middle=1.5`, 경계 여유 0.10 손 폭, 방향 확인 3개 연속 새 프레임이다. 확정되지 않은 방향 변경 중에는 기존 방향을 계속 울리지 않고 정지한다. 손이 옆으로 서 축이 모호하거나 너무 작으면 정지한다. 경계값은 `--near`, `--middle`, `--stable-frames`로 조정한다.

이 값은 **px 거리를 손 크기로 정규화한 시험 지표**이며 cm·깊이·물리적 접촉·집기 완료를 뜻하지 않는다. 3안 근접의 두 번 진동은 같은 상태의 정상 갱신으로 반복되지 않는다. STOP 뒤 재개하거나 near를 벗어났다가 들어오면 다시 발생할 수 있다.

## 6. 갱신·지연·정지

- BLE는 GATT Write with response, 약 100ms마다 sequence 증가, TTL 500ms다. 실제 200Hz PWM과 ON/OFF 패턴은 ESP가 생성한다.
- 영상의 기본 최대 나이는 **350ms**다. 처리 지연·손 상실·목표 상실·잘못된 데이터는 STOP한다. UDP를 받은 시각으로 원본 시각을 갱신하지 않는다. 기본 15fps라도 실제 추론 지연이 350ms를 넘으면 정지할 수 있으므로 먼저 프레임 처리 시간을 측정한다. `--max-age`를 늘리면 오래된 위치로 안내하는 시간이 길어진다.
- 단일 영상 프로세스의 IPC sequence와 frame_id는 증가해야 한다. 중복·역순 메시지로 신선도를 연장하지 않는다. 다른 프로세스가 동시에 보내면 기존 스트림이 조용해질 때까지 인수하지 않는다.
- 입력이 멈추면 송신부의 프레임 만료 검사로 STOP한다. 송신부 자체가 멈추면 ESP의 마지막 수신 후 TTL 만료가 작동한다. 무선 지연과 스케줄링이 있어 실제 정지 시간을 보장하는 센서 측정은 아니다.
- BLE 오류에서는 STOP을 시도하고 연결을 종료한다. 자동 재접속으로 안내를 재개하지 않는다. 원인을 확인한 뒤 송신부를 다시 실행한다.
- 상태 패킷 duty/ON은 ESP의 **논리 출력**이다. DRY_RUN에서도 나타날 수 있으며 모터 전류·진동 실측이 아니다.

## 7. 영상 프로그램 연결 전 독립 시험

BLE 없이 터미널 동작부터 확인:

```bash
python -m ble_sender --mode 2 --dry-run --allow-test
```

입력 예:

```text
test far in 2
mode 3
test middle th 2
test middle pi 2
test near mi 1
status
quit
```

실제 BLE 시험은 `--dry-run`만 빼고 실행한다. `test`는 최대 2초이며, 2안의 시험 채널도 `--rate-channel`과 일치해야 한다. 3안 near는 MI만 허용한다. 새 영상 관측이나 STOP이 들어오면 시험을 덮어쓴다. 이것은 모터/전송 시험이지 영상 인식 검증이 아니다.

| 파일 | 역할 |

| `ble_sender/protocol.py` | 16바이트 명령 인코딩·상태 디코딩 |
| `ble_sender/guidance.py` | 손 관절 축·거리 구간·연속 프레임 확인 |

| `ble_sender/cli.py` | 독립 실행·터미널 명령·100ms 갱신 |

PC 검사: Python 25개 통과. 실제 로컬 UDP 송수신, 모드 전환, 취소, 입력 정지, 오래된 프레임, 목표 변경, 손 뒤집기, 화면 회전과 가로세로 비율, sequence 순환, 종료 정지를 확인했다. 기존 ESP 펌웨어 헤더로 빌드한 C++ 라이브러리에 Python 패킷을 넣어 **24가지 유효 조합 × 80시점 = 1,920시점**의 출력 패턴과 TTL 만료를 대조했다. 정적 검사도 통과했다.

라즈베리에서 재검사 (`Raspi5_vision`에서 실행):

```bash
python -m unittest discover -s ble_sender/tests -v
# C++ 컴파일러가 있으면 ESP 패턴 엔진 대조까지 포함:
c++ -std=c++17 -Wall -Wextra -Werror -shared -fPIC \
```
