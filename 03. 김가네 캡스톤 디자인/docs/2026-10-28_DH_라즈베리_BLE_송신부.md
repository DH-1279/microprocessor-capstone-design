# 라즈베리 BLE 송신부 및 detector 자동 연결

작성일: 2026-10-28 / 작성: DH

작업 브랜치: `DH-1279/2026-10-28`

기준: 김가네 `5954c95`의 영상·음성 흐름과 [ESP32 BLE v2 수신 규격](2026-10-27_DH_ESP32_BLE_송수신규격.md).

## 1. 현재 통합 상태

**`KHS_KMJ_vision/detector.py`를 실행하면 BLE 작업도 자동으로 시작한다.** 별도 송신 터미널을 열거나 `python -m ble_sender`를 함께 실행할 필요가 없다.

```text
detector.py 실행
 → 내부 BLE 작업 시작 → ESP32 검색·연결 → 초기 STOP·상태 확인
 → 카메라·음성 초기화 → 시동어 대기
 → 물체 선택·락온 → 유효한 손/목표 좌표를 BLE 작업으로 전달
 → 2안/3안 명령 갱신 → ESP32가 선택 모터의 PWM 패턴 생성
```

연결 실패 시 BLE 없는 실행으로 조용히 넘어가지 않고 오류로 종료한다. ESP 없이 영상·음성만 확인하려면 명시적으로 `--no-ble`을 쓴다. 시동어·목표 선택 전에는 연결되어 있어도 진동 안내를 시작하지 않는다.

해수의 현재 흐름을 유지했다.

- 시동어 뒤 물건 선택 안내와 현재 목록을 한 번 재생한다. “리스트” 요청도 처리한다.
- 탐색 중 취소하면 물건 선택 단계로 돌아간다.
- 도달 판정 후에는 시동어 대기로 돌아간다.
- 손 미인식 음성은 기존 5초 간격을 유지한다.

목록의 3초 자동 반복이나 프로그램 설명 확장은 이번 통합에서 추가하지 않았다.

로컬에 브랜치가 없으면 `git switch`가 같은 이름의 원격 브랜치를 따라 생성한다. 기존 가상환경이 다른 위치에 있으면 그 `.venv/bin/activate`의 절대 경로를 사용하고, 실행 폴더는 위 `Raspi5_vision`으로 맞춘다. 카메라·Hailo·MediaPipe·음성의 기존 모델 및 의존성은 그대로 필요하다.

## 3. 실행은 detector 하나

```bash
python -u KHS_KMJ_vision/detector.py --mode 2
```

기본 모드는 2이므로 `--mode 2`를 생략해도 된다. ESP에는 `esp32_device/ble_final/firmware/ble_final_receiver`가 올라가 있어야 한다. BLE 이름 `KIMGANE-HAPTIC-V2`와 서비스 UUID로 자동 검색한다. 장치가 여러 개면 다음처럼 주소를 지정한다.

```bash
python -u KHS_KMJ_vision/detector.py --address XX:XX:XX:XX:XX:XX --mode 3
```

PuTTY에서 실행하면서 라즈베리에 연결한 HDMI 모니터로 미리보기를 볼 때는 기존처럼 다음 환경을 먼저 지정한다.

```bash
export DISPLAY=:0
export XDG_RUNTIME_DIR="/run/user/$(id -u)"
python -u KHS_KMJ_vision/detector.py
```

ESP가 `DRY_RUN=true`면 연결·논리 상태만 확인되고 실제 모터는 켜지지 않는다. 실제 모터 시험은 점검된 PCB에서 `DRY_RUN=false`로 업로드한다. **Pi의 `--dry-run`은 BLE 연결 자체를 생략하는 옵션**으로 ESP 펌웨어 설정과 다르다.

```bash
# ESP 없이 카메라·음성과 송신 매핑을 검사
python -u KHS_KMJ_vision/detector.py --dry-run
# 송신 작업 없이 기존 영상·음성만 실행
python -u KHS_KMJ_vision/detector.py --no-ble
```

## 4. 같은 터미널에서 모드 전환

ESP 시리얼 모니터가 아닌 **detector를 실행한 라즈베리 터미널**에 입력하고 Enter를 누른다.

| 명령 | 동작 |
|---|---|
| `mode 2` | 고정 손가락의 진동 간격 안내 |
| `mode 3` | 방향별 손가락 + 근접 두 번 진동 |
| `status` | 송신부 상태와 ESP 상태 패킷 조회 |
| `stop` | 즉시 정지, 새 영상이 와도 정지 유지 |
| `resume` | 터미널 정지 해제, 이후 새 프레임부터 안내 |
| `quit` | BLE 정지 후 detector도 종료 |

미리보기 창의 `q` 또는 Ctrl+C도 전체 종료 경로에서 BLE를 닫는다. 음성 “취소”는 기존 물건 선택 단계 복귀이며, 터미널 `stop`은 모터 안내의 수동 잠금이다. 잠금 중에는 음성으로 다시 목표를 골라도 `resume` 전까지 진동하지 않는다.

서로 다른 모드로 바꾸면 먼저 STOP을 전송하고 이전 좌표를 폐기한다. 이후 새로 촬영한 프레임으로 안내를 재개한다. 같은 모드를 다시 입력하면 패턴을 재시작하지 않는다.

## 5. 좌표와 동작 기준

BLE 코드는 `Raspi5_vision/ble_sender/`에 유지한다. detector는 같은 프로세스의 별도 작업 스레드에서 BLE 이벤트 루프를 실행한다. 영상 루프는 `VisionPublisher`로 Pi 내부 `127.0.0.1:8766`에 현재 관측을 전달한다. 카메라·Hailo·마이크를 중복해서 열지 않는다. 독립 송신 프로그램과 detector를 동시에 실행하면 같은 포트가 충돌하므로 둘 중 하나만 실행한다.

관측에는 새 프레임 번호, 원본 촬영 시각, 실제 화면 크기, 정규화된 손 21점과 목표 박스를 넣는다. 목표를 새로 락온할 때마다 다른 ID를 발급한다. 같은 이름의 물체라도 새 락온이면 이전 패턴·좌표를 이어받지 않는다.

손은 `hand="Any"`로 추적하여 장갑의 Left/Right 오분류를 허용한다. 물리적 착용 손 설정 `worn_hand="Left"`는 손바닥·손등 해석용이며 Right 라벨의 손을 거르는 설정이 아니다.

추적기에 `last_observed_landmarks`를 추가했다. 이번 프레임의 유효한 단일 손에만 값이 있고, 안정화 때문에 이전 손 위치를 유지한 프레임·여러 손·낮은 점수·잘못된 좌표에는 없다. detector의 BLE와 도달 판정은 이 관측을 사용한다. 화면 표시를 위한 기존 raw 값과 안정화 기능은 유지한다.

### 2안: 고정 검지 + 간격

검지 끝에서 목표 박스까지 영상상 최단 거리를 손바닥 폭으로 나눈다. 기본 채널은 IN이며 `--rate-channel TH` 등으로 바꿀 수 있다. 손을 뒤집어도 고정 채널을 유지한다.

| 구간 | ON | OFF |
|---|---:|---:|
| far | 200ms | 1000ms |
| middle | 200ms | 500ms |
| near | 200ms | 200ms |

### 3안: 손 기준 방향 + 근접

손 관절 축에 대해 목표 방향을 계산한다. 화면 회전과 가로세로 비율을 보정하며 MediaPipe의 Left/Right 라벨로 채널을 고르지 않는다.

| 방향 | 모터 |
|---|---|
| 엄지 쪽 | TH |
| 소지 쪽 | PI |
| 손끝 쪽 | IN |
| 손목 쪽 | RI |
| 영상상 근접 | MI, 120ms ON → 120ms OFF → 120ms ON 후 OFF |

근접은 손바닥 중심에서 목표 박스까지의 거리를 손바닥 폭으로 나눈 값이다. 기본 경계는 near=0.35, middle=1.5, 여유 0.10이며 방향은 3개 연속 새 프레임으로 확인한다. `--near`, `--middle`, `--stable-frames`로 조정한다. 손을 옆으로 세워 관절 축이 모호하면 정지한다.

현재 도달 판정은 기존의 **중지 밑 관절과 목표 중심 50px 이내, 5개 연속 프레임**을 유지하되, 새 유효 손·새 목표 관측이 있을 때만 누적한다. 도달 시 STOP이 근접 패턴보다 우선하므로 진행 중인 두 번 진동이 중간에 끝날 수 있다. 영상상 거리는 cm·깊이·접촉·실제 집기 완료를 증명하지 않는다.

## 6. 정지·지연·오류

- 안내 중 약 100ms마다 새 sequence를 보내고 ESP TTL은 500ms다. 실제 PWM 200Hz와 ON/OFF 패턴은 ESP가 생성한다.
- 기본 프레임 최대 나이는 350ms다. 촬영 시각을 추론 종료/수신 시각으로 바꾸지 않는다. 영상 작업이 막혀도 BLE 작업이 독립적으로 오래된 관측을 만료한다.
- 손/목표 상실, 음성 취소, 도달, 실행 종료는 STOP이다. 이전 `locked_target_box`를 새 관측으로 재전송하지 않는다.
- 연결/쓰기 오류가 생기면 detector가 오류를 보고하고 정지·종료한다. 자동 재접속으로 안내를 다시 켜지 않는다. 송신 작업이 완전히 멈추면 ESP TTL 만료가 마지막 방어다.
- `--max-age`를 늘리면 느린 추론을 수용하지만 오래된 위치로 안내하는 시간도 늘어난다. 실제 처리 지연을 확인한 뒤 조정한다.
- `--duties 180 180 180 180 180`은 TH/IN/MI/RI/PI 보정값이다. 각각 1..255, 한 번에 선택한 모터 하나에만 사용한다. 기본 180은 사용자 평가 전 시험값이다.
- ESP 상태의 ON/duty는 논리 출력이며 실제 전류·진동 측정값이 아니다.

## 7. 실물 시험 순서

1. ESP BLE v2 수신기를 켜고 detector만 실행해 연결 메시지를 확인한다.
2. 시동어 대기와 물건 선택 단계에서는 진동하지 않는지 확인한다.
3. “캡스톤” → 물건 이름으로 락온한 뒤 손을 보여 안내를 확인한다.
4. `mode 2`, `mode 3`을 바꾸고 손바닥/손등·방향·거리 구간을 비교한다.
5. 손을 가리거나 목표를 화면에서 빼서 정지를 확인한다.
6. 음성 “취소”, 터미널 `stop`/`resume`, 도달, `quit`를 각각 확인한다.

BLE·모터만 분리해서 검사하려면 detector를 종료한 뒤 `python -m ble_sender --mode 3 --allow-test`를 실행하고 `test middle th 2`, `test near mi 1`을 사용할 수 있다. 시험 명령은 최대 2초다.

## 8. 검증과 한계

PC 검사 38개가 통과했다. 실제 detector 루프에 카메라·음성·추론만 모의로 공급해 락온/취소/재선택/도달/손·목표 상실/오래된 프레임/예외 정지를 확인했다. 내부 BLE 작업과 실제 로컬 UDP를 연결한 검사, 초기화 실패와 연결 대기 중 종료 검사도 포함한다.

기존 ESP C++ 패턴 엔진과의 24개 유효 조합 × 80시점(1,920시점) 대조도 유지한다. 테스트는 아래 명령으로 실행한다.

```bash
python -m unittest discover -s ble_sender/tests -v
# C++ 컴파일러가 있으면 ESP 패턴 엔진 대조까지 포함:
c++ -std=c++17 -Wall -Wextra -Werror -shared -fPIC \
  ble_sender/tests/firmware_bridge.cpp -o /tmp/kimgane-ble-v2.so
HAPTIC_V2_LIB=/tmp/kimgane-ble-v2.so \
  python -m unittest discover -s ble_sender/tests -v
```

라즈베리 Bluetooth 어댑터·실제 ESP 무선 연결·장갑 모터 체감은 이 PC 검사에 포함하지 않았다. 실제 기기에서는 위 7절 순서로 확인해야 한다.
