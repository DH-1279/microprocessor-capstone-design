# 목표 영역 도달 알림과 다섯 손가락 BLE 제어

작성일: 2026-10-29 · 작성자: DH · 작업 브랜치: `DH-1279/2026-10-29`

## 변경 이유와 결과

기존 detector는 중지 뿌리 관절 9와 물체 중심이 50px 이내인 상태가 5프레임 지속되면 획득으로 표현했다. 손가락 끝과 물체 경계의 겹침을 사용하는 BLE 거리 안내와 기준이 달랐다. 물체 미검출을 화면에서 손에 가려짐으로 단정하던 표시도 수정했다.

- 현재 프레임의 유효한 손과 목표가 함께 관측되고, **같은 손가락 끝**이 물체 박스의 안쪽 80% 영역에 **0.4초** 유지되면 목표 영역 도달이다. 손 크기·자세 검증, 캡처 시각 및 기본 350ms 신선도 제한을 적용한다.
- 잠깐 스침, 손가락 교대, 가림으로 인한 목표 상실, 오래된 좌표는 유지 시간을 누적하지 않는다. 마지막 박스를 새 관측처럼 재사용하지 않는다.
- 이는 **2D 영상상의 위치 도달**이며 실제 접촉·집어 들기 판정이 아니다. 음성·로그도 목표 위치 도달로 표현한다. 가림이 유지 시간 전에 발생하면 도달이 성립하지 않을 수 있다.
- 도달 시 일반 안내 대신 **다섯 모터 모두 PWM 255/255(100%)**, 150ms ON → 150ms OFF → 150ms ON → OFF를 한 번 실행한다. 모터 전압을 높이는 기능이 아니다.
- 시동어 대기 화면으로 돌아가도 완료 알림을 중간에 자르지 않는다. 명시적인 stop/취소, 새 목표, 모드 변경, 종료, 무효 명령, TTL 만료, 연결 종료는 정지가 우선한다.
- 완료 음성 합성기가 바쁘면 다음 영상 루프에서 재시도한다.

## mode 2 / mode 3

mode 2 기본값은 엄지·검지·중지·약지·소지 각각의 끝점과 물체 사각형 사이 최단거리를 손 폭으로 나눈 값이다. 각 채널에 히스테리시스를 따로 적용하며 박스 내부에서는 거리 0 = near 안내를 유지한다.

| 구간 | 각 손가락 패턴 | 기본 세기 |
|---|---|---|
| far | 200ms ON / 1000ms OFF | 180 |
| middle | 200ms ON / 500ms OFF | 180 |
| near | 200ms ON / 200ms OFF | 180 |
| 도달 완료 | 다섯 채널 150ms ON / 150ms OFF / 150ms ON, 한 회 | **255 고정** |

`--duties TH IN MI RI PI`로 일반 안내만 보정한다. 각 채널 구간이 바뀌면 그 채널의 주기만 새로 시작하며, 단순 heartbeat는 위상을 유지한다. 여러 채널 동시 출력이 가능하다.

`--single-rate --rate-channel IN`은 예전처럼 mode 2 한 채널 시험이다. mode 3의 방향 선택·근접 중지 알림은 유지하고, 목표 영역 도달 이벤트는 동일하게 다섯 채널로 실행한다. 근접 중지 알림과 전체 완료 알림은 별도다.

## BLE v2 확장: 16바이트 유지

이 문서가 10월 27~28일 문서의 단일 채널·예약 바이트 설명보다 우선한다. 이름/UUID/16바이트 길이는 유지한다. 새 수신기의 상태 바이트 15는 capability bit0 다중 주기, bit1 도달 이벤트를 나타내며 값은 3이다. 송신기는 초기 STOP과 상태 읽기 뒤 이 값을 확인한다. 구형 수신기에는 모터 ON을 보내지 않고 업데이트 필요 오류를 낸다.

| 명령 byte 1 | 의미 | byte 6 | byte 7~8 | byte 10~14 |
|---|---|---|---|---|
| 0 | 기존 단일 채널 안내 | mode 2/3 | 기존 zone/channel | 채널별 보정 duty |
| 1 | STOP | 0 | 0 | 0 |
| 2 | 다중 주기 안내 | 2 | 리틀엔디언 10bit: TH부터 각 2bit 구간 0/1/2 | 다섯 보정 duty |
| 4 | 도달 한 회 이벤트 | 2/3 | 리틀엔디언 16bit 이벤트 ID, 1..65535 | 모두 255 |

byte 0=2, byte 2~3=sequence, byte 4~5=TTL, byte 9·15=0은 명령에서 유지한다. 플래그 조합은 허용하지 않는다. 상태 byte 9는 한 모터라도 논리 ON이면 1, byte 10~14는 실제로 명령한 논리 duty다. 다중 주기의 상태 zone/channel은 요약값 near/IN이며 다섯 구간은 Pi 송신 로그로 확인한다. 물리적인 모터 회전 측정은 아니다.

명령 쓰기 ACK 제한 1초와 ESP TTL 기본 500ms는 분리한다. 도달 이벤트는 ESP가 수신 시각부터 450ms 패턴을 자체 실행한다. 송신부는 최대 1.5초의 유한한 이벤트 전달 창에서 같은 ID를 갱신한다. 같은 ID는 STOP 또는 TTL 이후에도 재시작하지 않는다. 연결을 새로 맺으면 ESP 이벤트 기록이 초기화되지만 Pi는 완료한 lock ID를 재전송하지 않는다. 취소나 통신 실패 뒤 자동 재개하지 않는다.

Pi 내부 IPC의 일반 idle은 이미 시작한 완료 이벤트를 자르지 않는다. 명시적 STOP은 즉시 취소한다. 완료 이벤트도 유효한 같은 프레임의 관측에서만 최초 생성하며, 오래된 영상 좌표로 새 명령을 만들지 않는다.

## 적용 및 실기기 확인

1. 실행 중인 detector를 종료한다. 최신 코드를 받는다.
2. Arduino에서 `esp32_device/ble_final/firmware/ble_final_receiver/ble_final_receiver.ino`를 연다. 같은 폴더의 `pattern_protocol.h`도 최신이어야 한다.
3. ESP32-C3 Dev Module / USB CDC On Boot Enabled / Arduino-ESP32 3.3.11 / NimBLE-Arduino 2.5.1. 실제 진동 시험에는 스케치의 `DRY_RUN = false`로 바꾸고 업로드한다. 저장소 기본값은 true다.
4. Pi의 `Raspi5_vision` 폴더에서 실행한다.

```bash
source .venv/bin/activate
python -u -m ble_sender.check_link --address 9C:CC:01:82:75:8A
python -u KHS_KMJ_vision/detector.py --address 9C:CC:01:82:75:8A --mode 2
```

- 먼저 손가락별 먼/중간/가까움 진동 간격이 다른지 확인한다. 터미널 로그에 다섯 구간과 보정 duty가 표시된다.
- 한 손가락이 박스 안쪽에 0.4초 유지되면 전체 모터가 최대 PWM으로 정확히 두 번 울리는지 확인한다. 같은 목표에 반복되지 않아야 한다.
- 안쪽에 잠깐 들어갔다 나오기, 손가락 교대, 손/물체 가림, 취소/stop, 연결 종료 때 오검출·반복·출력 잔류가 없는지 확인한다.
- 도달 전에 물체가 가려져 사라지면 성공 알림 대신 안내가 멈추는 것이 현재 설계다. 실제 파지 판정이나 가려진 물체 추정은 별도 과제다.
- 최대 PWM 다섯 채널 알림 때 공급 전압과 전류, ESP 재부팅 여부를 실제 전원 구성에서 확인한다. PC 시험으로 전원 안정성과 체감 세기를 확정하지 않는다.

## 검증 범위

호스트에서 실제 C++ 패턴 엔진을 DLL로 빌드해 Python 패킷과 대조한다. 독립 주기, 최대 PWM 두 번 패턴의 정확한 경계, TTL 만료, STOP, 동일 이벤트 중복 억제, 구형 펌웨어 차단, 실제 detector 루프 → localhost UDP → 비동기 송신 경로를 검사한다. Arduino ESP32-C3 전체 빌드도 수행한다. 무선·카메라 실물·전원·착용 체감 시험은 사용자가 Pi와 장갑에서 수행해야 한다.
