# 손바닥 중심 획득 판정과 mode 3 지속 안내

작성일: 2026-10-29 · 작성자: DH · 작업 브랜치: `DH-1279/2026-10-29`

## 최종 요구사항

초기 구현의 손가락 끝 0.4초 겹침 판정을 폐기하고, 사용자가 요청한 손바닥 중심/잠금 목표 중심 기준으로 변경했다. 알림 시간은 후속 요청인 **350ms씩 두 번**을 적용한다. 이 문서가 이전 10월 27~29일 단일 근접 알림·가림 정지·450ms 완료 알림 설명보다 우선한다.

- 손바닥 중심: 손목과 손가락 뿌리 랜드마크 **0, 5, 9, 13, 17의 평균**. 중지 뿌리 하나나 손가락 끝을 중심으로 사용하지 않는다.
- 목표 중심: 현재 검출 또는 LOCKED 상태의 마지막 목표 박스 중심.
- 기본 임계값: 실제 영상 픽셀 좌표로 중심 사이 **50px 이내**, **5개 연속 유효 프레임**이면 획득으로 판정한다.
- 거리 이탈, 손 관측 상실·무효 좌표, 오래된/중복 프레임, 목표 변경은 카운터를 초기화한다. 같은 잠금 목표의 획득 이벤트는 한 번만 발생한다.
- 이 획득은 단안 영상의 2D 위치 규칙이다. 실제 손으로 쥐었는지 또는 깊이 방향 접촉을 별도로 측정하지는 않는다.

## 가림 상태의 안내

손이 물체를 가려 검출이 사라져도 **잠금 박스를 삭제하거나 45프레임 후 해제하지 않는다.** 취소/새 목표/획득 전까지 마지막 목표 위치를 유지한다. 새로운 물체 검출이 들어오면 기존 위치 매칭 기준 안에서 박스를 갱신한다.

손 좌표는 매번 현재 카메라 프레임의 유효 관측만 사용한다. 손은 기본 350ms 신선도 검사를 유지하며, 물체의 원래 마지막 관측 시각은 `target_seen_at`으로 별도 전달한다. 마지막 물체 좌표를 새로 검출한 것처럼 시간을 바꾸지 않는다. 화면에는 `LOCKED: 마지막 목표 위치로 안내 계속`이라고 표시한다.

이는 물체가 같은 자리에 있다는 잠금 가정이다. 가려진 동안 물체 자체가 움직였는지는 추적할 수 없으며, 위치를 다시 정하려면 취소 후 목표를 재선택한다. 손 인식 상실, 무효 자세/명령, 취소/stop, 종료, 통신 끊김에는 정지한다. mode 3 방향 투표 중에는 현재 손과 잠금 좌표가 유효한 동안 직전 확정 방향을 잠깐 유지해 불필요한 STOP을 줄인다.

## 진동 패턴

기본 실행 모드는 **mode 3**이다. 엄지 쪽 TH, 소지 쪽 PI, 손끝 쪽 IN, 손목 쪽 RI로 방향 안내하고, 근접 구간은 MI를 사용한다.

| 상황 | 출력 |
|---|---|
| far | 선택 채널 200ms ON / 1000ms OFF 반복 |
| middle | 선택 채널 200ms ON / 500ms OFF 반복 |
| near | 중지 200ms ON / 200ms OFF, 획득 전까지 반복 |
| 획득 | **다섯 모터 duty 255로 350ms ON → 200ms OFF → 350ms ON**, 한 회 후 OFF |

일반 안내는 기본 duty 180이며 `--duties`로 보정한다. 획득 알림은 보정값과 무관하게 255/255(100%)다. 모터 전압을 높이는 기능이 아니다. mode 2 다섯 채널 독립 주기와 `--single-rate` 시험 옵션도 유지한다.

## BLE 확장과 시간 제한

이름/UUID/명령 16바이트 길이는 유지한다. 명령 flags는 0 기존 단일 채널, 1 STOP, 2 다중 주기, 4 획득 이벤트이며 플래그 조합은 거부한다. 다중 주기는 byte 7~8에 TH부터 2bit씩 다섯 구간을 넣고, 획득 명령은 같은 위치에 이벤트 ID(1..65535)를 넣는다. 명령 byte 9·15는 0이다. 상태 byte 9는 어떤 모터라도 논리 ON이면 1이다.

상태 byte 15 capability는 **7(0x07)**이다: bit0 다중 주기, bit1 획득 이벤트, bit2 350ms 두 번 알림과 반복 근접 안내. Pi는 초기 STOP 뒤 이 값이 맞는지 검사한다. 이전 값 0 또는 3이면 업로드 필요 오류에 실제 값과 기대 값을 표시한다.

GATT 쓰기 ACK 제한은 1초다. 일반 안내 TTL은 500ms, 획득 이벤트 TTL은 1000ms다. 송신기는 최대 1.9초의 유한한 창에서 같은 이벤트 ID로 갱신하고, ESP는 최초 수신부터 정확히 900ms 패턴 한 회만 실행한다. 갱신은 패턴을 재시작하지 않는다. 같은 이벤트는 STOP/TTL 이후에도 다시 시작하지 않으며, 명시적 STOP과 연결 종료는 패턴 도중에도 즉시 OFF다.

## 업로드와 실행

ESP의 최신 스케치는 사용자가 지정한 기존 경로에 반영한다.

`03. 김가네 캡스톤 디자인/esp32_device/ble_final/firmware/ble_final_receiver/ble_final_receiver.ino`

같은 폴더의 `pattern_protocol.h`도 최신이어야 한다. 실기기용 기존 `DRY_RUN=false` 설정을 보존한다. Git 저장소의 기본값은 true이므로 다른 checkout에서 새로 열 때는 실제 시험 전 false로 설정한다. Arduino ESP32-C3 Dev Module / USB CDC On Boot Enabled / Arduino-ESP32 3.3.11 / NimBLE-Arduino 2.5.1을 사용한다.

Pi의 `Raspi5_vision`에서:

```bash
source .venv/bin/activate
python -u -m ble_sender.check_link --address 9C:CC:01:82:75:8A
python -u KHS_KMJ_vision/detector.py --address 9C:CC:01:82:75:8A --mode 3 --reach-px 50 --reach-frames 5
```

시동어 → 목표 선택 → mode 3 반복 안내 → 손바닥/목표 중심 획득 → 다섯 모터 350ms 두 번 + 획득 음성 → 시동어 대기 순서다. 화면과 로그에 `Palm-target` 거리 및 `Grab: 현재/필요 프레임`이 표시된다. 다른 프레임 크기를 사용하면 px 임계값도 실제 환경에 맞춰 조절한다.

## 검증

실제 C++ 패턴 엔진과 Python 패킷을 연동하여 350/550/900ms 경계, 반복 근접 진동, TTL/STOP, 이벤트 중복 억제를 검사한다. detector 루프에서 손이 물체를 가린 뒤 손바닥 중심이 겹쳐 획득되는 경우, 장시간 미검출 상태에서 잠금 유지, 손 상실 때 정지, 취소/재시작을 검사한다. 무선·실물 카메라·전원·착용 세기는 실제 장비에서 별도 확인한다.

획득 판정은 방향 안내의 손바닥/손등 축 검증과 분리했다. 손을 옆으로 돌려 방향 축이 불확실해도 유효한 손바닥 좌표가 있으면 중심 겹침 획득을 검사한다. 최종 Python/C++ 연동 75개 검사, ruff 검사, 기존 C++ 프로토콜 경계 12,523개 검사가 통과했다. Arduino-ESP32 3.3.11 / NimBLE-Arduino 2.5.1 / ESP32-C3 USB CDC 전체 빌드도 성공했다(플래시 585,837바이트 44%, RAM 23,760바이트 7%). 직접 ESP에 업로드하거나 실제 모터를 측정한 결과는 아니다.
