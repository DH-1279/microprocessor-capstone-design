## 1. QA에서 확인한 불편

| 항목 | 사용자 관찰 | 코드에서 확인한 동작 |
|---|---|---|
| 방향 안내 지연 | 물체를 선택한 뒤 손가락별 방향 안내가 늦게 들림 | WAV 캐시는 이미 있지만, 없는 문장은 요청 시점에 합성한다. 물체 이름과 공통 방향 설명이 한 문장으로 묶여 있어 다른 물체를 처음 선택하면 다시 합성한다. |
| 입력 준비음 | 소리가 작고 짧아 말할 타이밍을 알아차리기 어려움 | 준비음은 880Hz, 80ms, 파형 진폭 5,000으로 생성하고 있었다. |

실시간 합성은 지연 원인 중 하나다. 실제 지연에는 앞선 안내의 재생 대기, TTS 모델 로딩, 오디오 장치의 지연도 포함될 수 있다. 실기기에서 각 구간의 시간을 측정한 상태는 아니므로 합성만이 원인이라고 확정하지 않는다.

## 2. 안내 음성 사전 생성

### 변경한 방식

`prepare_audio.py`를 추가해 고정 문장과 물체별 안내 문장을 미리 WAV로 생성하도록 했다.

```text
최초 준비: 안내 문장 목록 → Supertonic 합성 → WAV 저장
실제 사용: 안내 이벤트 → 저장된 WAV 확인 → 재생 요청
```

- 시스템 시작, 방향 설명, 취소, 손 미인식, BLE 연결 상태 등의 고정 안내를 준비한다.
- 등록된 물체별 선택·부재·현재 목표·획득 안내를 준비한다.
- 저장 위치는 기존과 같은 `~/.cache/kimgane-haptic/tts`다.
- 정상 WAV가 있으면 재합성하지 않고, 누락되거나 읽을 수 없는 WAV만 생성한다.
- 준비 명령은 마이크·카메라·BLE를 열거나 음성을 재생하지 않는다.
- 실제 WAV 생성에는 라즈베리의 Supertonic 실행 환경이 필요하다. 첫 모델 다운로드에는 네트워크가 필요할 수 있다.

### 물체 안내와 공통 설명 분리

기존에는 다음 전체 문장을 하나의 캐시 항목으로 취급했다.

> 지갑을 찾아 안내합니다. 엄지는 오른쪽, 새끼는 왼쪽, 검지는 앞, 약지는 뒤, 중지는 근접입니다. 획득하면 전체가 두 번 울립니다.

변경 후에는 아래 두 문장을 하나의 재생 묶음으로 예약한다.

1. 물체별 문장: “지갑을 찾아 안내합니다.”
2. 공통 문장: “엄지는 오른쪽, 새끼는 왼쪽, 검지는 앞, 약지는 뒤, 중지는 근접입니다. 획득하면 전체가 두 번 울립니다.”

두 번째 선택부터 사용하는 짧은 공통 설명도 별도로 준비한다. 묶음 전체를 한 번에 예약해 문장 사이에 준비음이 끼어들지 않게 했으며, STT 처리 중 예약이 거절되면 묶음을 그대로 재시도한다.

현재 화면의 물체 목록처럼 조합이 달라지는 문장은 처음 요청할 때 합성하고 이후 캐시를 재사용한다. 모든 문장의 실시간 합성을 제거한 것은 아니다. 기존 앱 시작 시 TTS 모델 초기화도 유지한다.

## 3. 입력 준비음 개선

| 설정 | 변경 전 | 변경 후 |
|---|---:|---:|
| 길이 | 80ms | **250ms** |
| 파형 진폭 | 5,000 | **12,000** |
| 주파수 | 880Hz | 880Hz |
| 형식 | 16kHz, 모노, PCM16 | 동일 |

- `voice_profile.py`의 `ready_tone_ms`, `ready_tone_amplitude`로 조절한다.
- 준비음 파일명에 버전과 설정값을 포함해 기존의 짧고 작은 WAV를 재사용하지 않는다.
- 진폭은 디지털 파형의 크기이며, 스피커에서 느끼는 음량은 시스템 볼륨·출력 장치에도 영향을 받는다.

입력 허용 순서는 유지한다.

```text
예약된 안내 재생 완료 → 잔향 대기 300ms → 준비음 250ms
→ 꼬리 대기 약 50ms → 이전 입력 버퍼 정리 → 음성 입력 허용
```

준비음 재생 중에는 마이크 입력을 억제한다. 연속된 안내가 있으면 마지막 안내 이후에 준비음 한 번만 출력한다.

## 4. 지연 확인용 로그

| 로그 | 의미 |
|---|---|
| `TTS 대기` | 예약 후 음성 작업이 시작되기까지 걸린 시간 |
| `TTS 합성` | 캐시가 없어 파일을 생성하는 데 걸린 시간 |
| `TTS 캐시` | 기존 WAV를 확인해 재사용했다는 표시 |
| `TTS 재생 요청` | `aplay` 실행 직전의 재생 요청 표시 |

`TTS 재생 요청`은 실제 스피커에서 소리가 시작된 시각을 측정한 로그가 아니다. 지연이 남으면 대기·합성·출력 장치 구간을 나누어 확인한다.

## 6. 라즈베리에서 확인할 명령

개인 브랜치 `DH-1279/2026-11-02`를 라즈베리에 반영한 뒤 아래 순서로 확인한다. 사전 생성 시에는 기존 detector를 종료한다.

**실행 전 별도 확인:** 기준 커밋 `603f7c6`의 새 모델 메타데이터·NMS 설정은 10클래스인데, 기존 `config/labels.txt`와 음성 물체 목록은 11클래스다. 클래스 순서도 달라 그대로 추론하면 라벨이 잘못 대응할 수 있다. 이번 음성 개선 커밋에는 모델·라벨 정합 수정은 포함하지 않는다. 아래 detector 실행 전 해당 정합 문제를 해결해야 하며, 음성 사전 생성만으로 해결되지 않는다.

```bash
cd "$HOME/Desktop/kimGA_raspi/microprocessor-capstone-design/03. 김가네 캡스톤 디자인/Raspi5_vision"
source .venv/bin/activate

# 최초 한 번 생성. 재실행하면 정상 파일은 재사용한다.
python -u -m KHS_KMJ_vision.prepare_audio

# 파일 검사만 수행. 누락·손상이 있으면 종료 코드 1이다.
python -m KHS_KMJ_vision.prepare_audio --check

# 실제 안내 시험
export DISPLAY=:0
python -u KHS_KMJ_vision/detector.py \
  --address 9C:CC:01:82:75:8A \
  --mode 3 --reach-px 75 --reach-frames 8
```

준비 대상 문장만 확인하려면 `python -m KHS_KMJ_vision.prepare_audio --list`를 사용한다. 음성·물체 목록을 변경하면 사전 생성 명령을 다시 실행한다.
